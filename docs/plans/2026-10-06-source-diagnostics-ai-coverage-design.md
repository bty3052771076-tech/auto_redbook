# 信源诊断、每日 AI 覆盖与新闻主题精简

## 目标与边界

- 工作流和独立智能体都提供「信源健康」入口，检查已启用的新闻 API、统一 RSS 注册表及 AI 信源。
- 检测只读，不调用 LLM、不生图、不同步模型额度、不启动浏览器、不生成或上传帖子。
- API 检测会消耗新闻接口本身的请求次数；缺少密钥的接口显示「未配置」，不发请求。
- 保留本地生成记录、项目文档、人工关键词及已有运行中的冻结计划。

## 已确认的问题

1. `check-sources` 用生成采集器检查 AI，目标只有一条，无法证明未访问的信源是否可用。
2. 健康判定把 `stale`（连接成功但没有窗口内消息）计入故障率，可能长期降级官方公告源。
3. 工作流页面不会在检测结束后自动刷新；独立智能体没有信源检测入口。
4. 内置新闻主题分散在 CLI、任务计划和前端，用户指定关键词与默认大范围主题容易混淆。
5. 部分主页是动态网页或没有日期，HTTP 200 不等于可用新闻。实测 Qwen 页面空结果、MiniMax 新闻首页无日期；不得把抓取时间充当发布时间。

## 模块设计

### 只读诊断模块

新增 `src/sources/diagnostics.py`，复用现有解析器与 API 适配器，不另造新闻抓取实现。

- 目录：AI 已启用/未启用/未选择信源、配置好的新闻 API、公共检索流、统一信源注册表中的 RSS。
- 每个来源单独检查，最多四个采集线程；底层 HTTP 使用有限超时，不因已获得足够候选而提前结束。
- 结果包含连接状态、内容状态、材料数、有日期数、窗口内数量、最后发布时间、检查时间、耗时及操作建议。
- 分辨 401/403 权限错误、404 地址错误、429 限流、超时、解析失败、空结果、无日期、仅旧消息。
- 本地回环地址连接被拒绝单独显示「本地服务未连接」，提示按需启动对应服务并核对端口；不能误判为 API Key 故障。
- `stale` 不再触发故障冷却或替换；没有近期消息不等于接口失效。空结果和无日期仍提示解析/材料问题。
- 检测结果写入 `data/source_health/diagnostics_<collection>.json`；与生成采集快照隔离，防止检测改变生成的故障历史。
- 不接受用户传入任意 URL；只检查本地已配置目录。输出和落盘均去除 URL 认证参数、密钥及敏感报错。

### 界面

- 工作流复用原「信源健康」页面，智能体侧栏增加同名页面，不混入内容生成计划。
- 顶部提供范围、关键词、回溯天数、检测按钮、刷新按钮；显示分类计数、检测进度和逐源诊断表。
- 检查中禁用重复提交；结束后自动刷新。已缓存的记录明确展示检查时间，不能把旧快照当作实时检测。
- 未选择、未启用、未配置和未检测均独立呈现；不能显示成「正常」。
- 智能体 API 复用现有后台任务队列，沿用会话认证、请求校验、幂等键和单任务互斥。

### AI 来源与覆盖

- 增加经过实际解析验证的 Google AI、AWS AI、Microsoft Research 官方订阅流、MiniMax 官方带日期公告索引和 OpenAI Codex 发布订阅流。
- Codex 使用 Atom 小体积订阅流，避免 release JSON 响应超出现有下载上限。开发预览/常规补丁是否值得发布仍由原热度规则判断。
- 不把无法解析日期的首页加入默认可用信源；不绕过 X 限流，不虚构官方发布时间。
- 候选池模式即使官方数量足够，也检查已配置的聚合与社交线索，核验后才入稿。官方模型发布继续优先。
- 保留北京时间当日及前一自然日门禁、历史同事件去重、同一规范化来源最多两条、具体内容要求和热度要求。
- 不固定凑八条。现有单帖数量/正文/图片容量安全上限保留，在容量内纳入所有合格更新；检测报告的近期条数不代表已经通过发布审核。

### 新闻默认主题

- 单一默认值：`国际冲突 科技产业 社会民生 财经产业`。
- CLI、新任务计划、网页自动发帖预填保持一致；其他栏目不受影响。
- 用户提供关键词时替换默认检索主题，不悄悄追加体育、文化、品牌等词。
- 按关键词筛选仍是偏向，不新增分类配额硬限制；用户明确指定的要求通过原计划校准机制表达。
- 工作流对话入口复用独立智能体已有的本地关键词提取逻辑。

## 验证计划

1. 测试 stale 不冷却/不替换，真实超时仍按历史故障降级。
2. 用受控 API/RSS 响应验证全源检查、时间统计、日期计数、未来日期排除、认证参数脱敏及坏响应隔离。
3. 验证无密钥不访问、诊断不调用 LLM/生图/平台、不覆盖生成健康历史。
4. 验证默认四主题与自定义关键词替换；测试两个程序的 CLI/任务计划入口。
5. 回归 AI 两日门禁、历史查重、来源最多两条及完整标题/正文。
6. 前后端构建、认证接口测试和隔离浏览器桌面/手机检查；不在测试中生成或发布帖子。
7. 执行一次真实只读检测，记录当前不可达/限流/无近期内容，报告外部接口未解决的限制。
