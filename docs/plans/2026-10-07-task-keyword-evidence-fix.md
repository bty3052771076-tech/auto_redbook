# 任务关键词与大模型校准修复

日期：2026-10-07

## 目标与边界

- 修复本地识别漏掉关键词、侧边栏不展示关键词，以及大模型引用校验失败。
- 覆盖独立智能体和工作流内置对话页；保持本地规则优先、大模型校准由用户主动触发。
- 本轮不生成内容、不上传草稿、不发布、不同步额度、不更改已执行任务的冻结计划。
- 本地环境、密钥及测试产物保留在本地；不安装新依赖。

## 实证原因

1. 本地解析只支持带冒号的“关键词：”，没有覆盖“关键词为…”、“优先关注…”和“至少包含一条女性权益新闻”。
2. 旧正则一次吞掉后续栏目，导致关键词跨栏目污染或后一个栏目的关键词遗漏。
3. 独立智能体已渲染关键词，但后端没有填入；工作流对话页没有渲染关键词和选题说明。
4. 原校准输入把含默认主题的完整 prompt 当作 local_plan 交给模型。一次真实 MiniMax-M3 调用将“国际冲突 科技产业 社会民生 财经产业”当成用户原文引用，因而被校验拦截。
5. 校验同时要求 original_text 和 evidence_quote 逐字出现，容易将有真实引用支撑的解释性转述误判为无效引用。引用门禁本身仍需保留。

## 模块设计

### 共享本地主题解析

- extract_job_topics 统一返回 keywords、keyword_mode 和 topic_brief。
- 显式关键词是 filter：替换默认检索主题；带数字的下一个栏目和控制指令不属于关键词。
- “优先关注”“主要关注”及部分包含要求是 preference：保留默认选题方向，追加用户原文要求，不能将全部稿件限定为单一主题。
- 逐个处理关键词标记，以最近的栏目限定范围；以“新闻”结尾的包含要求归属每日新闻，避免因前面出现 AI 栏目而错误挂到 AI 资讯。
- 否定的包含/关注要求不转换成正向关键词。
- 保留关键词数量和长度校验、多词引用短语支持；不修改栏目篇数和任务交付方式。
- extract_job_keywords 保持原调用接口，规则计划和校准校验共用解析结果。

### 校准证据分离

- recognition_payload 只传栏目、篇数和关键词等对比信息，不传宿主默认 prompt 或默认选题说明。
- user_evidence 将当前用户消息切成带编号的原文连续片段；模型可以引用 @u1、@u2，也可逐字引用原文。
- 提示词明确 local_plan/defaults 不是用户证据，不能写成用户要求。
- 服务器将编号解析为原始片段，回填 original_text/evidence_quote；解释只放在 normalized_instruction。
- 伪造引用、未知编号、原文不存在的关键词仍拒绝；错误指出具体要求编号，保留旧计划，等待用户处理。
- 原有身份、幂等、配置指纹、计划版本、计费和执行确认门禁不变。
- 本地识别出的部分主题要求必须保留到校准计划，防止校准再次缩窄整个候选池。
- 分类硬篇数仍遵循宿主现有能力，不因识别成功而承诺可保证某主题篇数；有不支持项时返回待澄清而非悄悄忽略。

### 界面

- 两个界面均显示每个栏目的关键词/选题偏向和选题说明。
- 采用新计划、刷新页面后仍展示同一持久化字段；不存在字段的旧计划兼容空展示。
- 正在执行的计划不追溯改写。旧待执行计划应重新发送原始任务，或通过用户主动校准重新识别。
- 大模型校准失败不执行任务；校准成功仍需先采用，再确认执行。

## 验证计划

1. 规则回归：自然包含、无冒号、多栏目、下一栏数量、否定、显式关键词、默认方向保留。
2. 校准回归：宿主信息隔离、编号引用、解释性转述、无效引用、关键词/篇数/交付不可篡改，以及原有幂等与冲突测试。
3. GUI：用实际解析产物检查两个页面的侧栏；桌面和移动视口截图，验证无横向溢出、无执行请求。
4. 真实模型：仅调用当前 MiniMax 订阅做任务校准，不执行生成与平台操作，验证同一指令不再出现默认主题伪引用。
5. 完整回归与前端构建。结果以实际测试输出为准。

## 二次修复：编号与原文混合引用

### 故障复现

- 用户重启后保存的失败记录使用 task-recognition.v2-evidence.1，错误为要求 r1 引用了无效原文；原始模型输出未持久化，不能据此恢复当时的引用字符串。
- 使用同一条用户原句进行隔离的真实 MiniMax-M3 调用，复现了相同错误：模型返回 `@u1 生成10条每日新闻`。编号和附带原文均正确，但旧验证只接受单独的 `@u1` 或原文连续片段，误拒绝了混合格式。
- 首轮修复后的三次实测全部通过引用检查，但一次模型擅自把未指定的 skip_quota_sync 设为 false，造成无关的待澄清阻塞。该问题已另加回归并修复。

### 修复边界

- 新增 resolve_evidence_quote：支持单独编号、编号加原文、冒号分隔和一层匹配的引号；编号附带内容必须与该编号的用户原文完全一致。
- 未知编号、错误附带原文、转述或宿主默认提示词冒充用户原文仍拒绝，不增加模糊匹配，不丢弃错误的附带内容。
- 新增 RecognitionOutputError，失败记录保存字段位置、原因和经过现有脱敏器处理的引用诊断；schema 错误不保存包含凭据的输入值。
- skip_quota_sync 仅在用户原文同时指向额度及同步动作时才允许由识别结果修改；未要求同步时继承当前计划，明确禁止同步时保持跳过。明确请求但宿主不支持的额度同步仍返回待澄清。
- 提示词升级至 task-recognition.v2-evidence.2；公开 schema_version 仍为 task-recognition.v2。
- 失败保留原计划，成功仍需用户采用及确认，不自动重试或启动内容任务。
