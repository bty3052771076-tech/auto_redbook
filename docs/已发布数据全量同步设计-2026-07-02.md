# 已发布数据全量同步设计（2026-07-02）

## 背景

一次同步日志显示：

```text
[xhs-upload] collect_metrics: in_progress | items=317 target=322 scroll=81/240
[xhs-upload] collect_metrics: success | total=317
```

这里 `target=322` 来自小红书创作者中心页面的 `全部 N`，而最终只解析到 `317` 条。旧逻辑只要解析到任意有效数据就返回 success，会导致 `published_metrics_latest.csv` 被部分数据覆盖，后续发布方向分析会误以为这是全量样本。

## 新行为

默认严格全量：

- `--limit 0`：必须采集到页面显示的全部已发布数量。
- `--limit N`：必须采集到请求的 N 条；如果页面总数小于 N，则以页面总数为准。
- 如果页面显示 `全部 322`，最终只采集 `317`，CLI 会报错并拒绝覆盖 `published_metrics_latest.csv`。
- 如果页面目标数未知，`--limit 0` 不再把“已采集数量”反推成目标数，也不会把本轮判定为完整。
- 如果完全没有采集到有效数据，CLI 同样会报错并拒绝覆盖 `published_metrics_latest.csv`。
- 只有显式传入 `--allow-partial`，才允许保存部分结果。

## CLI

全量同步：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 0 --login-hold 600
```

已登录 profile 的无界面全量同步：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 0 --headless --login-hold 0
```

部分同步调试：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 0 --allow-partial --login-hold 600
```

当不完整且未允许部分同步时，CLI 输出类似：

```text
metrics-collection: fetched=317 target=322 required=322 missing=5 complete=False
error: incomplete published metrics; refusing to overwrite latest analytics ...
```

## GUI

`已发布数据` 页新增 `必须全量同步（缺失则失败，不覆盖 latest）`。

- 默认勾选。
- 勾选时不会传 `--allow-partial`。
- 取消勾选时会传 `--allow-partial`，允许把部分采集结果保存为 latest。
- GUI 不再为该功能暴露 `页面等待（秒）`，也不会向 `update-metrics` 传 `--wait-timeout`。
- 页面会在采集循环完成或明确判定本轮未完成后关闭，不会因为一个 GUI 页面等待输入到点就主动关闭。

`同步上限 limit` 的含义：

- `0`：全量同步，推荐默认值。
- `N`：同步请求范围为 N 条，严格模式下必须采集到 N 条。

## 停止条件

采集过程不使用固定页面等待时间作为总截止时间，但也不是无限等待。停止条件包括：

- 达到页面 `全部 N`。
- 达到用户指定的 `--limit N`。
- 达到 `XHS_METRICS_MAX_SCROLLS`，默认 `240`。
- 连续若干轮没有新增数据，默认 `XHS_METRICS_STAGNANT_ROUNDS=90`，最低 `18`。

`apps.cli update-metrics` 仍保留兼容性的高级 `--wait-timeout`，只用于单步 UI 等待，不作为全量同步的总运行时长。常规 GUI 和文档命令不再要求设置它。

页面入口保护：

- 默认只访问 `https://creator.xiaohongshu.com/new/note-manager`。
- 不再默认回退到旧的 `/creator/notes` 或发布编辑页，避免错误页面被当成已发布列表。
- 如果页面正文出现 `你访问的页面不见了` 等不可用提示，即使创作者中心外壳仍存在，也会判定为不可用页面并跳过或失败，而不是重新进入采集循环。

如果平台页面加载很慢，可临时调大：

```powershell
$env:XHS_METRICS_MAX_SCROLLS="400"
$env:XHS_METRICS_STAGNANT_ROUNDS="160"
```

## 实现文件

- `src/publish/playwright_steps.py`
  - 新增 `_published_metrics_collection_status(...)`。
  - `run_collect_published_metrics_sync(...)` 返回 `target_total / required_total / missing_count / complete`。
  - 部分采集会返回 `incomplete published metrics` 错误。
  - 默认已发布数据入口收敛到 `/new/note-manager`。
  - 识别 `你访问的页面不见了` 等错误页面，避免旧页面 route 造成循环采集。
  - `--limit 0` 且页面目标未知时，不再把本轮误判为完整。
  - 滚动过程中持续刷新 `全部 N` 目标数，避免初次读取过早导致 `target=unknown`。
  - 已发布卡片标题解析允许标题中包含 `点赞`、`浏览` 等普通语义词，并跳过 `未通过`、`查看修改建议` 等状态/操作行。
  - 无链接卡片合并键包含标题、发布时间和统计数字，避免同标题不同笔记被合并。
- `src/storage/files.py`
  - `published_metrics.jsonl` 和历史 CSV 继续追加历史快照。
  - `published_metrics_latest.csv` 只由本次同步快照生成，避免旧解析错误记录混入最新表。
- `apps/cli.py`
  - `update-metrics` 新增 `--allow-partial`。
  - 默认空结果或不完整时退出并拒绝保存 latest。
- `apps/gui.py`
  - 更新已发布数据页新增全量同步选项。
- `tests/test_published_post_sync.py`
  - 覆盖默认不完整不保存、允许部分才保存。
- `tests/test_published_metrics.py`
  - 覆盖 `317/322` 状态计算、目标未知时严格全量失败、旧页面入口不再作为默认候选、错误页面不会被创作者中心外壳误判为 ready、目标数后续刷新、标题解析和同标题不同日期合并。
- `tests/test_storage.py`
  - 覆盖 latest 只使用当前同步快照，不混入历史脏数据。
- `tests/test_gui.py`
  - 覆盖 GUI 参数和界面文案。

## 2026-07-02 真实同步复测

本轮先用小范围同步验证登录态和解析链路：

```powershell
$env:XHS_METRICS_MAX_SCROLLS="80"
$env:XHS_METRICS_STAGNANT_ROUNDS="24"
.\.venv\Scripts\python.exe -u -m apps.cli update-metrics --limit 20 --login-hold 30
```

结果：采集 `20/335`，用于诊断链路可用。

随后执行严格全量同步：

```powershell
$env:XHS_METRICS_MAX_SCROLLS="520"
$env:XHS_METRICS_STAGNANT_ROUNDS="180"
.\.venv\Scripts\python.exe -u -m apps.cli update-metrics --limit 0 --login-hold 30 --wait-timeout 90
```

结果：

```text
metrics-collection: fetched=330 target=335 required=335 missing=5 complete=False
error: incomplete published metrics; refusing to overwrite latest analytics ...
```

事件文件：`data/events/7eaa49a454b6468ab27ba811120036d1.json`。

该结果没有覆盖 `data/analytics/published_metrics_latest.csv`。随后进行 DOM 诊断，发现页面实际存在 `335` 个 `.note-card`：

- 旧解析器把标题中含 `点赞`、`浏览` 的真实标题排除，导致 2 条无效。
- `未通过` 卡片中的 `查看修改建议` 被当成标题，导致多条真实笔记被错误合并。
- 页面 `全部 335` 有时在初次读取时还未进入正文，滚动后才出现，旧逻辑不会刷新目标数。
- 历史 latest 生成逻辑会把旧解析错误记录混入最新表。

修复后再次执行严格全量同步：

```powershell
$env:XHS_METRICS_MAX_SCROLLS="520"
$env:XHS_METRICS_STAGNANT_ROUNDS="220"
.\.venv\Scripts\python.exe -u -m apps.cli update-metrics --limit 0 --login-hold 0 --wait-timeout 90
```

最终结果：

```text
metrics-collection: fetched=335 target=335 required=335 missing=0 complete=True
metrics: fetched=335 saved=335
posts-synced: matched=263 unmatched=72
event: data\events\c3edf219c3014cd59862b7e903abacc8.json
```

`data/analytics/published_metrics_latest.csv` 已更新为本轮严格全量快照，CSV 数据行 `335`，文件时间 `2026-07-02 23:41:36`，旧脏标题 `查看修改建议` 数量为 `0`。
