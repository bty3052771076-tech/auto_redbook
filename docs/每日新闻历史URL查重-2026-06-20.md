# 每日新闻历史 URL 查重

## 目标

每日新闻生成时，如果新候选新闻的网址已经在本地历史草稿中使用过，则跳过该候选，继续选择其他新闻，避免重复生成和重复上传同一条新闻。

## 查重范围

系统会读取本地历史记录：

```text
data/posts/<post_id>/post.json
```

重点读取以下字段：

- `platform.news.source_url`
- `platform.news.picked.url`

这些字段只保存新闻原始链接，不包含任何 API Key。

## URL 规范化规则

查重前会把 URL 转成稳定 key：

- scheme 和域名转小写
- 去掉 fragment，例如 `#comments`
- 去掉末尾 `/`
- 去掉常见追踪参数，例如 `utm_source` / `utm_campaign` / `fbclid` / `gclid`
- 保留非追踪 query，并按 key 排序

示例：

```text
HTTPS://Example.com/news/123/?utm_source=x&b=2&a=1#comments
```

会规范化为：

```text
https://example.com/news/123?a=1&b=2
```

因此同一新闻链接即使带不同追踪参数，也会被识别为重复。

## 默认行为

历史 URL 查重默认开启。每日新闻候选进入标题相似度去重后，会再经过历史 URL 去重：

1. 如果候选 URL 已在本地历史记录中出现，跳过该候选。
2. 如果同一 query 下候选全被跳过，继续尝试下一个 query 或下一个新闻源。
3. 如果最终没有剩余候选，CLI 会在“获取新闻”阶段失败，并在错误中体现没有可用新闻。

关闭方式：

```powershell
$env:NEWS_HISTORY_DEDUPE="0"
```

重新开启：

```powershell
Remove-Item Env:NEWS_HISTORY_DEDUPE -ErrorAction SilentlyContinue
```

## 元数据

每次新闻候选获取结果会在 `platform.news.history_dedupe` 中记录摘要：

```json
{
  "enabled": true,
  "used_count": 12,
  "skipped_count": 1,
  "skipped": [
    {
      "title": "Duplicate news",
      "url": "https://example.com/news/123?utm_campaign=new#section",
      "key": "https://example.com/news/123"
    }
  ]
}
```

这能帮助判断“为什么某条新闻没有被生成”：如果 `skipped_count` 大于 0，说明它被历史 URL 查重过滤了。

## 测试

新增测试覆盖：

- URL 规范化会去除追踪参数和 fragment。
- 历史 post 中已有同一 URL 时，新候选会被跳过，并保留后续未重复候选。
- `history_dedupe` 元数据会记录开启状态和跳过数量。

验证命令：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_daily_news.py -q
```
