# GUI 启动与运行稳定性修复（2026-06-22）

## 问题现象

运行 GUI 或相关启动脚本时，Windows PowerShell 5.1 可能弹出安全提醒：

```text
Invoke-WebRequest 分析页面时可能会运行网页中的脚本代码，存在安全风险！
建议使用 "-UseBasicParsing" 开关来避免脚本代码执行。
```

同时，GUI 在执行 `auto` / `run` / `delete-drafts` 这类长任务时，可能表现为日志区不稳定、按钮重复触发或窗口看起来卡住。

## 根因排查

- 仓库自己的 `Start-GUI.cmd`、`Open-XHS-Creator.cmd`、`scripts/start_gui.ps1`、`scripts/open_xhs_creator.ps1` 没有直接调用 `Invoke-WebRequest`。
- 该弹窗属于 Windows PowerShell 5.1 的旧 IE 解析路径提示，可能由间接网络请求触发；正确规避方式是在脚本进程内为 `Invoke-WebRequest` 启用 `UseBasicParsing`。
- GUI 的更核心稳定性问题在于后台命令线程直接写 Tkinter 文本控件。Tkinter UI 操作应回到主线程执行，否则长时间输出日志时可能出现随机卡顿或异常。
- `CommandRunner` 之前只在子进程创建完成后才能被判定为运行中，用户快速重复点击按钮时存在短暂竞争窗口。

## 修复内容

- `apps/gui.py`
  - 新增 `UiEventQueue`，后台线程只把日志/退出码放入队列。
  - Tk 主线程通过 `root.after(...)` 定时消费队列并更新日志区。
  - `CommandRunner.run(...)` 在启动线程前立即设置运行态，防止重复点击启动多个任务。

- `scripts/start_gui.ps1`
  - PowerShell 5.1 下设置 `$PSDefaultParameterValues["Invoke-WebRequest:UseBasicParsing"] = $true`。

- `scripts/open_xhs_creator.ps1`
  - 同步设置 `UseBasicParsing`，防止快捷入口间接触发 PowerShell 安全弹窗。

- `scripts/build_gui_exe.ps1`
  - 同步设置 `UseBasicParsing`，构建轻量启动器时保持一致行为。

## 使用建议

- 如果已经打开旧 GUI 窗口，请先关闭旧窗口，再重新运行：

```powershell
.\Start-GUI.cmd
```

- 如果仍看到 PowerShell 的 `Invoke-WebRequest` 安全提醒，优先选择“否”，关闭旧窗口后重新启动。当前仓库启动脚本已规避该提示；若仍出现，通常说明还有外部脚本、PowerShell Profile 或旧窗口进程在运行。

## 验证记录

```powershell
.\.venv\Scripts\python.exe -m py_compile apps\gui.py
.\.venv\Scripts\python.exe -m pytest tests\test_gui.py -q
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\open_xhs_creator.ps1
```

结果：

- `apps/gui.py` 语法检查通过。
- `tests/test_gui.py`：33 passed。
- `open_xhs_creator.ps1` 可正常执行，无 `Invoke-WebRequest` 安全弹窗。
- GUI 受控启动烟测：进程可启动并保持运行，stderr/stdout 为空。
