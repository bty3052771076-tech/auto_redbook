# GUI 发布草稿列表为空修复（2026-06-30）

## 问题现象

用户反馈 GUI 的 `发布草稿` 页看不到任何草稿，怀疑新增 `每日AI讯息` 后影响了旧发布功能。

## 根因

本次排查确认发布链路本身没有被 `每日AI讯息` 直接破坏，问题来自 GUI 本地草稿列表筛选逻辑：

1. `发布草稿` 页默认把发布日期设置为当天，北京时间 `2026-06-30`。
2. 当前本地数据中当天没有 `已上传且未发布` 的草稿，因此默认日期筛选结果为 0。
3. 即使清空日期，旧实现也会先取最近 200 个本地 post，再过滤可发布草稿；大量最近失败/已发布记录会把历史可发布草稿挤出这 200 个候选，导致仍显示为空。
4. CLI `publish-drafts --all --limit 1` 过去按文件系统顺序选草稿，可能优先选到很旧、已不在平台草稿箱中的陈旧本地记录。

## 修复内容

- `apps/gui.py`
  - `list_publishable_drafts()` 改为先扫描全部 `data/posts/<post_id>/post.json`，再过滤可发布草稿，避免先截断再过滤。
  - `发布草稿` 页默认日期改为空，初始显示全部本地已上传且未发布草稿。
  - 当日期为空且未选择具体 post 时，GUI 构造 CLI 命令会自动传 `--all`，避免 CLI 报“缺少 date/post_id/--all”。

- `apps/cli.py`
  - `publish-drafts --all --limit N` 改为按 `uploaded_at / updated_at / created_at` 倒序选择，优先处理最新上传草稿，和 GUI 展示顺序一致。

## 验证结果

本地数据验证：

- 修复前：`list_publishable_drafts(date="", limit=0)` 返回 `0`。
- 修复后：`list_publishable_drafts(date="", limit=0)` 返回 `565` 条本地可发布草稿。
- 当天筛选：`date="2026-06-30"` 返回 `0`，说明用户看到空表的直接原因是默认日期筛选当天没有可发布草稿。

