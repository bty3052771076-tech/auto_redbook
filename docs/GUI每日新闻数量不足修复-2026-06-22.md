# GUI 每日新闻数量不足修复（2026-06-22）

## 背景

在 GUI 的“自动发帖”页配置 `标题=每日新闻`、`数量=3`、图片来源为 `aliyun` 后，CLI 命令正确带上了 `--count 3`，但最终只生成并上传了 1 条草稿。

## 根因

- 每日新闻流程会先拉取候选新闻，再经过标题、正文、来源、站点噪声等质量闸门过滤。
- 旧逻辑只尝试 `max(count * 5, count + 10)` 个候选；当 `count=3` 时通常只尝试 15 个候选。
- 新闻源返回的摘要/正文质量参差不齐，严格过滤后可能只剩 1 条可用草稿。
- 旧逻辑会把这 1 条作为“成功结果”返回给后续上传流程，导致 GUI 看起来执行成功但数量不满足用户设置。

## 修复

- `create_daily_news_posts(...)` 现在会为多条每日新闻尝试更多候选：`max(count * 20, count + 30)`，默认新闻候选池可覆盖更多有效项。
- 如果最终生成数量少于 `--count`，流程会抛出明确错误，不再把部分草稿返回给上传流程。
- 错误信息会包含 `created only x/y`、候选尝试数、失败数和质量跳过数，便于判断是新闻源不足、LLM 内容质量不足还是图片生成失败。
- GUI 在运行 `auto` / `create` 且标题为 `每日新闻`、数量大于 1 时，会自动注入 `NEWS_MAX_RECORDS=max(60, count*20)`，同时强制子进程使用 UTF-8 输出。

## 用户可见行为

- 如果 GUI 选择 `数量=3`，系统会尽力生成 3 条。
- 如果新闻源或生成质量不足以满足 3 条，任务会失败并在终端/GUI 日志中显示原因，而不是只上传 1 条。
- 如果用户手动设置了更大的 `NEWS_MAX_RECORDS`，GUI 会保留更大的值。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_gui.py tests\test_daily_news.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

结果：

- `153 passed`
- `234 passed`

新增覆盖：

- GUI 多条每日新闻会自动扩大 `NEWS_MAX_RECORDS`。
- 每日新闻前 15 个候选被质量闸门跳过时，流程会继续向后寻找直到满足 `count`。
- 如果候选耗尽仍不足 `count`，流程会抛错，不把部分草稿交给上传流程。
