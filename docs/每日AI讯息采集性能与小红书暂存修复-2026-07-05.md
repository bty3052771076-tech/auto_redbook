# 每日AI讯息采集性能与小红书暂存修复（2026-07-05）

## 背景

实测 `每日AI讯息` 时出现两个问题：

- 生成阶段长时间只显示“运行中”，用户无法判断卡在哪个来源或窗口。
- 生成出的本地稿件虽然满足 8 条规则，但保存到小红书创作者中心时出现 `draft save verification failed`。

本次目标是用默认回溯规则生成 1 条 `每日AI讯息`，排查并修复链路问题，最终保存到小红书草稿箱。

## 问题原因

### 采集阶段

旧实现默认按 `3 -> 7 -> 14` 天自动扩展时，会对每个窗口重新发起完整网络采集。AI 官方源、GitHub、AI HOT 和搜索补充全部重复请求，容易出现 10 分钟以上的长等待。

搜索补充还会把默认查询再次展开成多条每日新闻查询，造成请求数膨胀，并触发新闻源限流或降级到无日期热榜，最后又被时间窗口过滤掉。

国内模型资讯不足不是“7 天内一定没有新闻”，主要是来源和解析不足：

- `ZCode`、`DeepSeek`、`ByteDance Seed` 等国内模型/工具官方源没有纳入。
- 部分官网把发布日期写在页面级 `Date`、`published_at` 或 Next 数据中，而不是新闻标题附近，旧解析器没有把页面日期应用到发布项。

### 小红书暂存阶段

小红书发布页的暂存按钮当前由自定义组件渲染：

```html
<xhs-publish-btn is-save-draft="true" save-text="暂存离开" save-disabled="false"></xhs-publish-btn>
```

普通文本 locator 读不到组件内部按钮，旧逻辑退到坐标点击。坐标点击有时能保存，但校验阶段可能过早判断失败，造成重复尝试和同名草稿。

## 修复内容

### 采集与筛选

- 默认自动扩展时只按最大窗口采集一次，然后在本地分别筛选 3、7、14 天窗口。
- 增加采集进度输出，终端/GUI 能看到来源、搜索补充和窗口筛选阶段。
- AI HOT、官方源、搜索补充增加可配置短超时：
  - `AI_DIGEST_SOURCE_TIMEOUT_S`，默认 8 秒。
  - `AI_DIGEST_AIHOT_TIMEOUT_S`，默认 8 秒。
  - `AI_DIGEST_SEARCH_BACKFILL_TIMEOUT_S`，默认 12 秒。
- AI 讯息搜索补充禁用每日新闻的提示词二次扩展，只按 AI 讯息默认查询获取。
- 新增国内官方源：`zcode`、`deepseek`、`bytedance-seed`。
- HTML 解析增加页面级发布日期提取，并对官方详情页只保留最强发布项，减少同页重复条目。

### 小红书暂存

- `_click_draft()` 新增 iframe 按钮查找。
- 新增 `document.elementFromPoint` DOM 点击兜底。
- 新增 `<xhs-publish-btn>` 专用点击：读取 `save-text/save-disabled`，优先点击 shadow DOM 内部保存按钮。
- 保存 after-fill / after-save HTML 证据，便于后续页面结构变化时复盘。

## 注意事项

本次修复前的几次重试也可能已在小红书草稿箱落地，因此草稿箱里可能存在同名 `每日AI讯息` 旧测试草稿。保留最新一条 `保存于2026-07-05 09:59:18` 即可；旧同名草稿可在创作者中心手动删除。
