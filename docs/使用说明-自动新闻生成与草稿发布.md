# 使用说明：自动新闻生成、AI 配图与小红书草稿保存

本文面向日常使用，说明如何启动 GUI、生成新闻、使用 AI 配图、保存到小红书创作服务平台，以及如何避免 API Key 被上传到仓库。

已发布稿件点赞/评论/收藏同步、运行记录表格和批量生成部分成功保护，请见：`docs/发布数据同步与运行记录-2026-06-27.md`。

## 1. 安全约定

本项目不会把真实 API Key 写入需要提交的文件。请使用以下任一方式配置密钥：

- 推荐：在 PowerShell 当前会话中设置环境变量。
- 可选：复制 `docs/*api-key.example.md` 为同名去掉 `.example` 的本机文件，例如 `docs/aliyun_image_api-key.md`。

真实密钥文件已被 `.gitignore` 忽略：

- `.env`、`.env.*`、`.env.gui`
- `docs/*api-key.md`
- `data/`
- `logs/`
- `exports/`
- `*.pem`、`*.key`、`*.p12`、`*.pfx`

提交前建议执行：

```powershell
git check-ignore -v docs/aliyun_image_api-key.md docs/llm_api-key.md docs/news_api-key.md docs/gnews_api-key.md docs/juhe_api-key.md docs/pexels_api-key.md .env .env.gui data/browser/chrome-profile
git status --short
```

如果曾经误把 key 提交到远程仓库，请立即到对应平台作废并重新生成 key。

## 2. 快速启动

启动 GUI：

```powershell
.\AutoRedbookGUI-Launcher.exe
```

如果还没有生成 exe，可使用：

```powershell
.\Start-GUI.cmd
```

或：

```powershell
.\.venv\Scripts\python.exe -m apps.gui
```

生成轻量启动 exe：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_gui_exe.ps1
```

生成结果：

```text
AutoRedbookGUI-Launcher.exe
```

说明：`AutoRedbookGUI-Launcher.exe` 只是启动器，会调用当前工作区的 `.venv\Scripts\pythonw.exe -m apps.gui`。旧的 `AutoRedbookGUI.exe` 是历史打包产物，不再推荐使用。

打开小红书图文创作页：

```powershell
.\Open-XHS-Creator.cmd
```

该脚本使用工作区内的浏览器 profile：

```text
data/browser/chrome-profile
```

GUI 顶部按钮“打开小红书创作平台”和“登录/检查Profile”也会使用同一个 profile。若 Chrome 安装位置或账号 profile 需要手动指定，可设置：
```powershell
$env:XHS_CHROME_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe"
$env:XHS_CHROME_USER_DATA_DIR="E:\AI\codex\redbook_workflow\data\browser\chrome-profile"
$env:XHS_CHROME_PROFILE="Default"
```

不要切换到其他 Chrome profile，否则可能看不到同一批草稿。

## 3. GUI 使用流程

GUI 页签说明：

- `自动发帖`：生成内容、AI 配图、上传图片并保存小红书草稿。
- `草稿处理`：查看本地草稿，显示标题、是否已上传到小红书草稿、最近执行结果、素材数量和正文预览；时间会单独在“时间（北京时间）”框中展示。
- `删除草稿`：预览或删除小红书创作服务平台里的草稿。
- `配置`：保存本机 `.env.gui` 配置，并查询阿里云百炼 / 火山引擎 Ark 免费额度；该文件已被忽略，不会上传。

2026-07-01 起，GUI 不再提供“仅生成”页签。需要保存到小红书创作者中心草稿箱时，请直接使用 `自动发帖` 或 CLI `auto`。

GUI 运行长任务时会在日志区显示心跳和状态。如果看到“仍在运行”，通常表示正在等待新闻 API、LLM、VLM 生图或小红书页面响应，不是窗口冻结；若等待过久，可点击“停止当前任务”后用终端命令复现。

推荐 GUI 参数：

- 标题：`每日新闻`
- 评价视角：`无视角评价`（默认）；如需特定角度可填写 `产业政策视角` / `消费者视角` / `投资者视角`
- LLM 供应商：`aliyun`
- LLM 模型：`qwen3.7-plus`
- 配图来源：`aliyun`
- 阿里云生图模型：`wan2.7-image`
- 素材 glob：`assets/empty/*`
- `login-hold`：首次登录建议 `600`，已登录可用 `0`
- `wait-timeout`：建议 `300`

## 4. 命令行生成新闻并保存草稿

以下命令会从新闻 API 获取新闻，由 LLM 写成中文小红书图文草稿，并优先使用阿里云 AI 生图保存到小红书草稿箱。

如果不提供 `--keywords`，系统会从默认通用主题池随机排序并抓取候选新闻，不再固定查询 `china`。如果想固定主题方向，建议填写 `--keywords`，或用 `NEWS_QUERY_DEFAULT` 自定义一个或多个默认 query。`--prompt` 仍可使用，用于兼容旧脚本。

```powershell
$env:LLM_PROVIDER="aliyun"
$env:ALIYUN_LLM_MODEL="qwen3.7-plus"
$env:ALIYUN_LLM_MODELS="qwen3.7-plus"
$env:IMAGE_PROVIDER="aliyun"
$env:ALIYUN_IMAGE_MODEL="wan2.7-image"
$env:ALIYUN_IMAGE_MODELS="wan2.7-image"
# $env:ALIYUN_IMAGE_MODEL="qwen-image-2.0-pro-2026-04-22"  # 手动测试 Qwen Image 时取消注释
$env:ALIYUN_IMAGE_SIZE="1104*1472"
$env:ALIYUN_IMAGE_TIMEOUT_S="240"
$env:ALIYUN_IMAGE_DOWNLOAD_TIMEOUT_S="90"
$env:ALIYUN_IMAGE_MAX_ATTEMPTS="2"
$env:ALIYUN_IMAGE_NEGATIVE_PROMPT="no text, no words, no letters, no watermark, no logo, no caption, no subtitle, no signature, no UI"
$env:NEWS_PROVIDER="juhe"
$env:JUHE_NEWS_APPKEY="YOUR_JUHE_NEWS_APPKEY"
$env:JUHE_FINANCE_NEWS_APPKEY="YOUR_JUHE_FINANCE_NEWS_APPKEY"

.\.venv\Scripts\python.exe -m apps.cli auto --title "每日新闻" --keywords "科技产业 / 社会民生 / 国际安全" --evaluation-viewpoint "无视角评价" --assets-glob "assets/empty/*" --count 1 --login-hold 0 --wait-timeout 300 --force
```

生成 3 条：

```powershell
.\.venv\Scripts\python.exe -m apps.cli auto --title "每日新闻" --keywords "科技产业 / 社会民生 / 国际安全" --evaluation-viewpoint "无视角评价" --assets-glob "assets/empty/*" --count 3 --login-hold 0 --wait-timeout 300 --force
```

## 5. 新闻内容规则

每日新闻会按以下规则处理：

- 系统会按上传数量抓取约 2 倍候选新闻，再按关注度、时效性和来源多样性筛选，不会拿到第一批候选就直接生成。
- 同一候选如果包含多条热榜/列表式新闻，会先选择最重要或最匹配的一条新闻，再生成标题、正文、评价和图片提示。
- 如果新闻是英文，必须改写为简体中文。
- 如果新闻是日文或其他语言，必须转写成简体中文，不保留日文假名。
- 标题必须是 12-18 字的中文总结标题，理想约 15 字，不再自动添加 `每日新闻｜` 前缀。
- `评价视角` 会写入内部生成规则。默认 `无视角评价`，不会预设国家、行业、投资者或平台立场；填写自定义视角时，评价仍必须基于已给事实和原文摘录。
- 正文最终是可直接发布的简体中文文本，按 `内容`、`评价`、`日期`、`来源` 四段展示，四段之间都保留空行，不会把 JSON 原文或 `原文标题` 写进小红书正文。
- `内容` 150 字以内，会清理浏览器升级提示、栏目导航、素材地址和空泛模板句。
- `评价` 有事实支撑时才写；如果无法客观评价，会保留为空字符串。
- `日期` 使用 `YYYY-MM-DD`。
- `来源` 只写来源名称。
- 正文不输出 URL，包括 `http(s)://`、`www.` 和 `//images...` 这类协议相对图片链接。
- 系统默认会尝试读取原新闻正文，再让 LLM 严谨总结；如果仍无法补足信息，只允许保守表述，不得推测。
- 原始 URL 只保存在本地 `data/posts/<post_id>/post.json`：
  - `platform.news.source_url`
  - `platform.news.picked.url`

这能保证发布内容更干净，同时本地仍可追溯来源。

## 6. 删除草稿

删除前务必先 dry-run：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --all --limit 0 --dry-run --login-hold 0 --wait-timeout 300
```

确认无误后再真实删除：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --all --limit 0 --yes --login-hold 0 --wait-timeout 300
```

说明：

- `--limit 0` 表示不限量。
- `--all` 会处理 image、video、article 三类草稿。
- 删除作用于当前登录的浏览器 profile。
- 如果小红书页面改成分页或懒加载，删除命令只能保证处理当前页面采集到的草稿列表。

## 7. 草稿复查与发布

本项目自动化默认只保存草稿，不公开发布。

复查草稿箱：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --limit 0 --dry-run --login-hold 0 --wait-timeout 300
```

在小红书创作服务平台中人工检查：

- 标题是否准确。
- 正文是否严谨、无内部指令泄漏。
- 图片是否合适且无文字水印。
- 来源和发布时间是否符合预期。

确认无误后，再由你在页面中手动点击公开发布。

## 8. 常见问题

新闻源不可用：

- `NEWS_PROVIDER=auto` 会尝试已配置的 NewsAPI / GNews / Juhe，最后再使用无需 Key 的 `hotnews` 热榜兜底。
- `GDELT` 已移除，不再作为免费回退源，避免仅凭低质量摘录生成草稿。
- 如果在线 API 临时不可用，改用 `NEWS_PROVIDER=file` 加载已核验候选。

草稿箱看不到刚保存的草稿：

- 多半是 Chrome profile 不一致。
- 使用 `Open-XHS-Creator.cmd` 打开工作区 profile。

生成内容出现 `????`：

- 通常是 PowerShell 管道脚本编码问题。
- 直接在命令参数里传中文一般正常；不要把含中文的 Python 脚本通过错误编码管道输入。

阿里云生图被内容安全拦截：

- 系统会跳过失败候选并继续尝试后续新闻。
- 可调整检索关键词，避免政治敏感、血腥、冲突等图片场景。

## 9. Git 上传前检查

提交前建议运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider -q
git status --short
git diff --cached --name-only
git ls-files | Select-String -Pattern "api-key\.md$|(^|/)\.env($|\.)|data/|chrome-profile|\.key$|\.pem$|\.p12$|\.pfx$"
```

如果最后一条输出为空，表示当前已跟踪文件中没有这些敏感路径。

## 10. 备份建议

上传新版本前建议创建备份分支和标签：

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
git branch "backup/pre-upload-$stamp" HEAD
git tag "pre-upload-$stamp" HEAD
git push origin "backup/pre-upload-$stamp"
git push origin "pre-upload-$stamp"
```

如果后续需要回滚，可从备份分支或标签恢复。
