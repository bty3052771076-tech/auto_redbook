# GUI 删除草稿 total=0 诊断

## 现象

GUI 生成的命令类似：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --draft-location publish --limit 0 --yes --login-hold 600 --wait-timeout 600
```

输出：

```text
type=image total=0
未找到草稿
```

这不一定代表小红书草稿箱真的没有草稿。

## 根因

`delete-drafts` 为了避免误删，会先执行一次预览枚举。旧逻辑在预览阶段如果遇到错误，例如：

- 没打开正确的小红书 profile。
- 当前 profile 未登录。
- 小红书页面没有成功打开草稿箱。
- 页面 DOM 或标签切换没有枚举到 `.draft-item`。

CLI 会返回 `total=0`，但没有把 `errors` 打印出来，导致用户误以为“草稿箱为空”。

## 修复

- `apps/cli.py`：预览结果如果包含 `errors`，现在会打印 `errors: [...]`。
- 如果预览失败，CLI 会输出 `预览草稿失败，未执行删除` 并以非 0 状态退出，不再继续显示误导性的 `未找到草稿`。
- `tests/test_cli_delete_drafts.py`：新增回归测试，覆盖 `total=0 + errors` 的提示行为。

## 验证命令

安全预览：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --draft-location publish --limit 0 --dry-run --headless --login-hold 0 --wait-timeout 600
```

本次验证结果：

```text
type=image total=20
```

说明当前 workspace Chrome profile 的小红书图文草稿箱可以被正确枚举。

## 使用说明

- `--limit 0` 表示不限制数量，不是删除 0 条。
- 建议先运行 `--dry-run --headless` 确认 `total` 和前 5 条标题。
- 如果 dry-run 正常，再去掉 `--dry-run` 并保留 `--yes` 执行删除。
- 如果出现 `errors:`，先按错误提示检查登录态、profile 和页面入口，不要直接判断为没有草稿。
