# 每日新闻多故事候选裁剪（2026-07-01）

## 现象

部分新闻源会把一个热榜条目包装成单个候选，但 `description` 或 `content` 实际包含多条无关新闻标题。例如一个候选标题是“长鑫存储一季度暴赚合肥十年赌局翻盘”，正文候选里同时混入：

- 苹果涨价、英伟达返现、OpenAI 发芯片
- 泡泡玛特暴涨、段永平收益
- 全球无电人口数据

旧逻辑会把这些多条新闻一起传给 LLM。结果可能出现正文讲 A 新闻、标题或图片提示词带到 B/C 新闻的问题。

## 根因

每日新闻流程在 `_enrich_daily_news_item()` 之后直接把 picked 新闻传给 `_daily_news_prompt()`：

```text
新闻标题 + 摘要 + 原文正文 -> LLM prompt -> body/title/image_event -> 自动配图
```

如果源候选本身就是“多条热榜标题列表”，LLM 会把这些标题视作同一篇新闻的上下文；图片生成也会继续沿用混杂后的 `image_event` 或 picked 元数据。

## 修复

新增 `_focus_daily_news_item()`，在候选进入 LLM 前执行一次单故事聚焦：

- 对 `description` / `content` 按行清洗，识别短标题式热榜列表。
- 用 picked 标题作为上下文，保留最相关的一条故事线。
- 带中文句末标点的正常多段正文不会被当作热榜标题列表裁剪。
- 单篇入口 `create_post_with_draft(title_hint="每日新闻")` 和批量入口 `create_daily_news_posts()` 共用这一步。
- `post.platform.news.multi_story_filter` 会记录本次是否裁剪，以及裁剪前后的字符数。

## 注意

修复只影响新生成的草稿。已经生成或已经上传的小红书草稿不会自动改正文或改图，需要删除后重新生成。
