# 每日新闻候选池筛选与正文规范（2026-07-02）

## 背景

每日新闻此前存在四类问题：

- 个别 API 会把多条新闻塞进同一个候选的 `description` / `content`，后续 LLM 容易把标题、正文、评价或配图串到不同事件。
- 草稿正文里仍展示 `原文标题`，不符合当前小红书正文格式要求。
- LLM 或新闻源返回繁体字时，最终草稿可能混入繁体中文。
- 候选新闻过于依赖单一来源，例如 `36kr.com`，且批量生成时容易拿到候选后直接开始生成。

## 设计

### 候选池扩大

`create_daily_news_posts()` 和 `create_post_with_draft(title_hint="每日新闻")` 现在共用候选池入口：

```text
请求数量 count -> target_fetch_count = count * NEWS_SELECTION_POOL_FACTOR
```

默认 `NEWS_SELECTION_POOL_FACTOR=2.0`，并限制在 `1.0` 到 `5.0` 之间。也就是说，生成 10 条时默认先抓约 20 条候选，再筛选；单条 GUI 生成也会先抓约 2 条候选。

筛选元数据会写入：

```text
post.platform.news.selection_pool
```

包含 `requested_count`、`target_fetch_count`、`actual_candidate_count`、`selection_policy` 和 `source_domain_max_ratio`。

### 来源多样性

`pick_news_items()` 新增单域名上限控制：

```text
NEWS_SOURCE_DOMAIN_MAX_RATIO=0.5
```

默认同一域名最多占目标数量的 50%。当候选池里存在其他来源时，`36kr.com` 这类单一域名不会继续占满全部草稿。若真实候选只有一个域名，则不会强行丢弃候选。

### 关注度和时效性

新闻候选新增 `attention` 字段，优先读取 API 返回里的热度、阅读量、分数等字段：

```text
score / hot / heat / hot_score / rank_score / views / view_count / read_count
```

没有显式热度时，使用标题和正文中的公共事件信号做轻量评分，例如政策、监管、调查、处罚、事故、收购、上市、暴涨暴跌等。排序时综合：

- 用户提示词相关性
- 跨来源重复度
- 关注度评分
- 发布时间
- 中国/海外比例配置
- 来源域名多样性

当前实现没有默认调用额外 LLM 做候选重排，原因是候选选择发生在正式生成前，额外 LLM 重排会增加供应商成本和失败面；目前先用可解释、可测试的本地评分完成筛选。后续如果需要 LLM rerank，可以在候选池获取之后，把同一批候选和上述评分一起交给 LLM 输出候选 ID，再复用现有质量闸门。

## 单故事聚焦

`_focus_daily_news_item()` 会在 LLM 生成和自动配图之前执行。

处理规则：

- 对 `description` / `content` 按行清洗，识别热榜式短标题列表。
- 如果候选标题是 `今日要闻`、`热点新闻`、`财经早报` 等泛化标题，会按重要性信号选择最重要的一条。
- 如果候选标题本身已经具体，则优先选择与候选标题最相关的一条。
- 普通多段正文带有句末标点时不会被误裁剪。
- 裁剪结果记录在 `post.platform.news.multi_story_filter`。

## 草稿正文规范

最终保存到本地草稿和上传到小红书的正文只包含四段：

```text
内容：
...

评价：
...

日期：YYYY-MM-DD

来源：来源名称
```

不再输出：

```text
原文标题：...
```

内部仍然兼容读取旧 JSON 或旧五段正文里的 `原文标题`，用于质量校验和旧测试数据输入；但 `_render_daily_news_body_fields()` 不会把它写入发布正文。

## 简体中文保障

每日新闻草稿在保存前会经过 `_simplify_daily_news_draft()`：

- `title`
- `body`
- `topics`
- `image_event`

都会做常见繁体到简体的本地转换。该转换不依赖外部包，没有新增安装步骤，也没有写入 C 盘。

## 配置项

```powershell
$env:NEWS_SELECTION_POOL_FACTOR="2.0"
$env:NEWS_SOURCE_DOMAIN_MAX_RATIO="0.5"
```

一般不需要修改。若候选质量很差，可以适当把 `NEWS_SELECTION_POOL_FACTOR` 调到 `3.0`；若希望进一步限制单一来源，可以把 `NEWS_SOURCE_DOMAIN_MAX_RATIO` 调低到 `0.3`。

## 验证

新增和更新的关键回归测试覆盖：

- 四段正文不再渲染 `原文标题`。
- 单 API 候选里有多条新闻时，会选择更重要的一条。
- 草稿保存前统一简体中文。
- 批量生成会按 `count * 2` 请求候选池。
- 候选池存在替代来源时，同一域名不会占满结果。
- 单条 GUI/CLI 入口也使用同一候选池逻辑。

## 注意

该修复只影响新生成的草稿。已经保存到本地或已经上传到小红书创作者中心的旧草稿不会自动改正文，需要删除后重新生成。
