# 每日新闻多 API 信源扩充与质量实测（2026-07-18）

## 目标

为 `每日新闻` 增加 NewsData.io、Alpha Vantage、TheNewsAPI、Finnhub 四个已配置的 API 信源，避免候选长期集中在单一聚合站点；同时保留既有聚合数据、NewsAPI、GNews、公开 RSS、BBC RSS 和热点榜回退链路。

本次只读取公开新闻标题、摘要、发布时间、原始链接和公开配图地址，不绕过登录、付费墙或访问控制。

## 本地配置与安全

- 本地凭据文件：`docs/news_sources_api-key.md`，已被 `.gitignore` 的 `docs/*api-key.md` 规则忽略。
- 可提交模板：`docs/news_sources_api-key.example.md`。
- 环境变量优先级高于本地文件，可使用 `NEWSDATA_API_KEY`、`ALPHAVANTAGE_API_KEY`、`THENEWSAPI_TOKEN`、`FINNHUB_API_KEY`。
- 可通过 `NEWS_SOURCES_CONFIG_FILE` 指向其他本地配置文件，便于测试环境隔离。

真实 key、响应原文和运行快照都不进入 Git。

## 接入实现

代码位于 `src/news/daily_news.py`：

- 自动模式检测到对应凭据后，依次纳入 `newsdata`、`thenewsapi`、`alphavantage`、`finnhub`。
- 每条 `NewsItem` 保存 `provider`，候选池在去重后按提供商轮转，并限制单一域名占比；避免先返回的大来源提前填满原始池。
- TheNewsAPI 使用实时的 `/v1/news/top` 端点，并传递 `search`、分类和发布时间窗口。此前 `/all` 在本账号实测中混入 2022 年历史记录，不能作为每日新闻入口。
- NewsData 当前账号的单次 `size` 上限按 10 条处理，避免请求 20 条造成 422。
- 聚合数据在“全来源候选池”阶段只读取列表摘要，不逐篇调用详情接口；最终被选中的新闻仍会沿用后续正文素材补取逻辑。
- 全来源模式默认每个 API 最多使用两个查询变体，RSS/热点源有更短的请求预算；`NEWS_EXHAUSTIVE_PROVIDER_QUERY_LIMIT`、`NEWS_EXHAUSTIVE_PROVIDER_TIMEOUT_S`、`NEWS_EXHAUSTIVE_RSS_TIMEOUT_S` 和 `NEWS_EXHAUSTIVE_OFFICIAL_RSS_DOMAIN_LIMIT` 可按网络情况调整。

## 真实探针与适用领域

探针日期为 2026-07-18（北京时间窗口三天内）。逐源原始结果保存在本地忽略目录 `data/source_probes/`。

| 信源 | 实测结果 | 更适合的方向 | 使用定位 |
| --- | --- | --- | --- |
| NewsData.io | 科技、财经、国际、体育四类测试均返回 10 条近期记录，单主题有 9 至 10 个域名 | 综合新闻、科技、国际、社会、体育的广覆盖候选 | 新增主力广覆盖源；有来源名、国家、语言、摘要和常见配图字段 |
| Alpha Vantage | 科技与财经测试均返回 20 条近期记录；财经约 8 个域名、科技约 10 个域名 | 财经产业、上市公司、市场、芯片和 AI 资产相关 | 财经产业补充主力；使用其主题映射和相关性字段，不用于体育或民生主源 |
| Finnhub | 财经测试返回 20 条近期记录，来源集中在 Reuters、CNBC、Bloomberg 等约 3 个域名；加密/并购也可稳定返回 | 全球公司、市场变化、财报、并购、加密资产 | 高可信财经补充；接口按新闻分类而非全文语义检索，必须保留域名占比限制 |
| TheNewsAPI | 实时 `/top` 在四类测试中返回 1 至 3 条近期记录，带摘要、语言和图片 | 国际要闻、跨国公司、政策补充 | 小量国际补充；当前免费额度返回量低，不能单独承担候选池 |

既有来源的定位保持不变：聚合数据优先补中国大陆公开新闻，NewsAPI/GNews 提供综合国际搜索，Google News RSS（含中国大陆官方域名限定）和 BBC RSS 提供无 key 回退，热点榜仅补热度而不作为日期可信主源。

## 全量候选池实测

使用本地已配置凭据，以 `technology artificial intelligence`、三日窗口、50 条原始候选上限运行自动全来源模式。为验证全链路，本次临时将每源查询数设为 1、官方 RSS 域名数设为 1；生产默认仍为两个查询变体。

结果：

- 11 个来源均完成，无 provider error。
- 合并后得到 50 条候选，覆盖 32 个新闻域名。
- 平衡后的来源分布为：聚合数据、NewsData、TheNewsAPI、NewsAPI、GNews、Alpha Vantage、Finnhub、Google News RSS（中/国际）、BBC RSS、热点榜均有候选；TheNewsAPI 因当前可见结果少，保留 3 条，其余来源各约 4 至 5 条。
- 聚合数据 28 条均有日期，且候选阶段耗时约 10.8 秒；说明“逐条详情请求”瓶颈已被移除。
- NewsData、TheNewsAPI、Alpha Vantage、Finnhub 均成功返回有日期候选。此次单轮耗时约 11.9 至 15.5 秒/源。
- 中国区 Google RSS 和热点榜在当前网络下较慢（约 51.9 秒、23.4 秒）；两者仍可用，但应视为补充源，运行进度会持续显示当前阶段，避免误判为卡死。

快照文件：`data/source_probes/integrated_source_health_fast.json`（本地忽略，不提交）。

## 后续使用建议

- `财经产业 / 公司政策 / 市场变化`：优先 Alpha Vantage + Finnhub，再使用 NewsData、NewsAPI/GNews 扩大叙事与地区覆盖。
- `国内政策 / 科技产业 / 民生`：优先聚合数据 + NewsData + 中国大陆官方 RSS 限定查询；国内配额仍由最终筛选规则保证。
- `国际科技 / 文化 / 体育`：优先 NewsData、NewsAPI/GNews、TheNewsAPI 与 BBC RSS；TheNewsAPI 只作补充。
- 最终草稿仍必须以原始链接、发布时间、提示词相关性、历史去重和来源多样性共同筛选，不能因某一 API 返回量大而直接采用。
