# hot_news 新闻源接入（2026-06-29）

## 背景

`orz-ai/hot_news` 提供无需 API Key 的热榜接口：`https://orz.ai/api/v1/dailynews`。它适合作为新闻候选兜底源，但不是全文新闻 API，也不应替代 NewsAPI、GNews、聚合数据 Juhe 这类可提供更完整新闻字段的来源。

本项目已将它接入为 `NEWS_PROVIDER=hotnews`，并在 `NEWS_PROVIDER=auto` 时作为最后兜底：

1. 已配置 NewsAPI 时优先尝试 `newsapi`。
2. 已配置 GNews 时继续尝试 `gnews`。
3. 已配置聚合数据 Juhe 时继续尝试 `juhe`。
4. 上述来源未配置或调用失败时，最后尝试 `hotnews`。

`NEWS_PROVIDER=file` 和 `NEWS_CANDIDATES_FILE` 仍然优先于自动在线源，适合使用人工核验过的候选缓存。

## 配置

强制使用 hot_news：

```powershell
$env:NEWS_PROVIDER="hotnews"
.\.venv\Scripts\python.exe -m apps.cli auto --title "每日新闻" --assets-glob "assets/empty/*" --count 1 --login-hold 600 --wait-timeout 600
```

指定平台顺序：

```powershell
$env:NEWS_PROVIDER="hotnews"
$env:HOTNEWS_PLATFORMS="jinritoutiao,sina_finance,cls,baidu,weibo,hackernews"
```

可选环境变量：

- `HOTNEWS_BASE_URL`：默认 `https://orz.ai/api/v1/dailynews`。
- `HOTNEWS_PLATFORMS`：逗号、分号、换行或竖线分隔的平台列表。

默认平台：

- `jinritoutiao`
- `sina_finance`
- `cls`
- `baidu`
- `weibo`
- `hackernews`

## 本地追溯字段

每日新闻保存到本地 `data/posts/<post_id>/post.json` 时，会写入：

- `platform.news.api_source`：最终采用的新闻 API，例如 `hotnews`、`gnews`、`juhe`。
- `platform.news.provider_plan`：自动模式计划尝试的新闻源顺序。
- `platform.news.provider_attempts`：本次真实调用过的新闻源。
- `platform.news.source_api.provider`：最终新闻 API。
- `platform.news.source_api.base_url`：API 基础地址，不包含 Key。
- `platform.news.source_api.platforms`：hot_news 平台列表。
- `platform.news.source_api.item_source`：候选项来源标记，例如 `hotnews:jinritoutiao`。
- `platform.news.source_api.item_domain`：原始 URL 域名。
- `platform.news.source_api.item_url`：原始 URL，仅保存在本地，不写入小红书正文。

这些字段不包含任何 API Key，可用于复盘“这条草稿来自哪个新闻 API、哪个平台、哪个 URL”。

## 注意

- hot_news 是热榜聚合候选源，部分平台返回的是搜索页或话题页链接，不一定是完整新闻正文。
- 项目仍会尽量抓取原文、清洗正文、生成中文摘要，并经过每日新闻质量闸门。
- 如果需要更严谨的新闻正文，优先使用 GNews、NewsAPI、聚合数据 Juhe，或使用 `NEWS_PROVIDER=file` 输入人工核验候选文件。
- `NEWS_PROVIDER=gdelt` 仍然不支持，避免回到低质量摘录路径。

## 验证

新增测试覆盖：

- hot_news API 返回字段映射为 `NewsItem`。
- 自动模式无 Key 时会使用 `hotnews`。
- NewsAPI 等 keyed provider 失败后会继续尝试 `hotnews`。
- 单条与批量每日新闻保存到本地时都会写入 `api_source` 和 `source_api`。
