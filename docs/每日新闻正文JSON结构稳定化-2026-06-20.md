# 每日新闻正文 JSON 结构稳定化

## 目标

每日新闻的中间层可继续识别和归一化 5 字段 JSON，但最终保存到 `post.body` 并上传到小红书的内容必须渲染为可读中文正文，而不是 JSON 原文。

内部字段固定为：

```json
{
  "原文标题": "新闻原始标题的中文化表达",
  "内容": "150 字以内中文正文",
  "评价": "可为空字符串；有事实支撑时才写客观评价",
  "日期": "YYYY-MM-DD",
  "来源": "来源名称"
}
```

最终发布正文渲染为：

```text
原文标题：...

内容：
...

评价：
...

日期：YYYY-MM-DD

来源：来源名称
```

正文中不放 URL、链接、`source_url` 或其它元信息；原始链接只保存在本地 `post.json` 的 `platform.news.source_url` 与 `platform.news.picked.url`。

## 实现

- `src/workflow/create_post.py`
  - `_daily_news_prompt(...)`：要求 LLM 外层仍返回 `title/body/topics`，但 `body` 字符串必须是可直接发布的五字段文本，不再要求内层 JSON。
  - `_daily_news_body_to_fields(...)`：无论 LLM 返回旧标签正文、JSON 字符串、还是离线兜底正文，都先提取为 `原文标题/内容/评价/日期/来源` 五字段。
  - `_render_daily_news_body_fields(...)`：把五字段渲染为可读正文；当正文过长时优先缩短 `内容`，再缩短 `评价`，确保不超过图文正文长度限制。
- `src/llm/generate.py`
  - `_coerce_text(...)`：当模型直接把 `body` 返回成中文字段对象时，保留完整字段，后续由 `_daily_news_body_to_fields(...)` 提取并渲染。
  - 通用系统提示仍要求普通正文可直接发布；每日新闻只在内部兼容 JSON/字段对象输入。
- `src/images/auto_image.py`
  - `_body_snippet_for_prompt(...)`：自动配图会从 JSON 输入或渲染正文的 `内容/评价` 字段提取事件信息，避免把字段名或花括号带入生图提示。

## 测试

新增/更新回归：

- 单条每日新闻最终 `post.body` 不是 JSON 原文，而是可读正文，包含 `原文标题/内容/评价/日期/来源`。
- 批量每日新闻最终正文不含 URL，来源和日期写入可读文本字段。
- 超长正文裁剪后仍保留来源和日期，且长度不超过 1000 字符。
- LLM 返回 `body` 对象时能保留完整 5 字段结构。
- AI 配图从 JSON 输入或渲染正文中读取 `内容/评价`，不把字段名当成画面内容。

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_daily_news.py tests\test_llm_generate.py tests\test_auto_image.py
```
