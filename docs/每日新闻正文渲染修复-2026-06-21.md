# 每日新闻正文渲染修复

## 问题

用户反馈小红书正文被写成整段 JSON，例如：

```text
{
  "原文标题": "...",
  "内容": "...",
  "评价": "...",
  "日期": "...",
  "来源": "..."
}
```

根因是此前为了稳定每日新闻正文结构，将 `_finalize_daily_news_body()` 的最终返回值改成了 5 字段 JSON 字符串；上传逻辑直接使用 `post.body`，因此 JSON 被原样写入小红书正文。

## 修复

- `src/workflow/create_post.py`
  - 新增 `_daily_news_body_to_fields(...)`：从 JSON、旧标签正文或普通正文中提取 `原文标题/内容/评价/日期/来源`。
  - 新增 `_render_daily_news_body_fields(...)`：将五字段渲染为可直接发布的正文文本，五段之间统一保留空行。
  - `_finalize_daily_news_body(...)` 不再返回 JSON 原文，而是返回渲染正文。
  - `_daily_news_prompt(...)` 不再要求 `body` 字符串本身是 JSON 对象文本，改为要求 `body` 是可直接发布的五字段正文。
  - 标题提示词改为 12-18 字、理想约 15 字，并要求 LLM 概括长标题而不是机械截断。
  - `内容` 字段统一压缩到 150 字以内，并移除浏览器升级提示、栏目导航、素材编号、协议相对图片链接和空泛方法论句式。
  - `NEWS_SOURCE_LOOKUP=1` 时默认尝试抓取原新闻正文，保留上限可用 `NEWS_SOURCE_LOOKUP_MAX_CHARS` 调整。
  - URL 清理扩展到 `//images...` 这类协议相对图片链接，避免来源页素材地址进入正文。
- `src/publish/playwright_steps.py`
  - 富文本编辑器兜底填充改为写入分段 HTML，空行用独立段落保留，避免 `textContent` 把正文压成一行。
- `src/images/auto_image.py`
  - `_body_snippet_for_prompt(...)` 兼容渲染后的五字段正文，只提取 `内容/评价`，避免字段名进入 AI 生图提示。

## 最终正文格式

```text
原文标题：...

内容：
...

评价：
...

日期：YYYY-MM-DD

来源：来源名称
```

如果没有可核验评价，`评价` 可以为空或省略具体内容；URL 不进入正文，只保存在本地 `post.json` 的 `platform.news.source_url` 和 `platform.news.picked.url`。

## 验证

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_daily_news.py -q
.\.venv\Scripts\python.exe -m pytest tests\test_auto_image.py -q
```

验证点：

- `_finalize_daily_news_body()` 输入 5 字段 JSON 时，输出不再以 `{` 开头，且不能被 `json.loads()` 当成正文 JSON。
- `_finalize_daily_news_body()` 输入已经渲染好的五字段正文时，会保留 `原文标题/内容/评价/日期/来源`，不会被旧 `要点摘要/新闻内容/点评` 兼容逻辑误改。
- 生成的每日新闻草稿 `post.body` 不包含 URL，也不包含旧标签 `要点摘要/新闻内容/点评`。
- 生成的每日新闻草稿会在 `原文标题/内容/评价/日期/来源` 五段之间保留空行。
- `//images...` 这类协议相对图片链接会被清理出正文。
- 自动配图从渲染正文中提取事件内容，不把 `原文标题/日期/来源` 当成画面提示。

## 2026-06-21 二次截图复核修复

后续真实上传和截图检查又发现并修复了几类边界问题：

- 标题不再机械截断长标题；例如 `中国举办人权理事会边会共商全球人权治理` 会压缩为 `中国共商全球人权治理`，不会出现 `全球人权治` 这种半词截断。
- 标题会去掉 `香港故事丨/记者手记丨/新华视点丨` 等栏目头，并修复中文引号不成对的问题。
- `原文标题` 保留中文来源原题；外文标题才由 LLM 中文化，不再被草稿短标题覆盖。
- 原文清洗会在 `〖纠错〗/阅读下一篇/深度观察/新华全媒+` 等推荐阅读区域前截断，避免把站内推荐文章写进正文。
- 正文会清理 `新华社发（某某摄）`、`新华社记者某某摄`、`新华社某地某日电（记者...）` 和残缺记者署名片段。
- 若 LLM 正文出现来源材料不支持的高风险表述，会用来源标题/摘要/原文摘录重新压缩事实段。
- 若评价套错类别，例如文化新闻写成 AI 版权模板、外交新闻写成经贸供应链模板，会替换为事实支撑的评价或留空。
- 每日新闻本地话题会过滤 `饭局/职场中的人情世故/凝聚力提升` 等无关话题，并按内容补充保守相关话题。

## 2026-06-21 标题照搬与错题模板加固

针对复核反馈继续加固：

- 草稿短标题不得与 `原文标题` 完全一致。即使来源原题本身在 20 字以内，也要改写为小红书短标题；例如 `古巴外长称美国无权评判古巴改革` 会改写为 `古巴回应美国评判改革`。
- LLM 提示词明确要求 `title` 不得直接照抄新闻原始标题，也不得与 body 中 `原文标题` 完全一致。
- 当正文已经混入站内推荐串（如 `香港故事丨...`、`权威数读丨...`、`新华视点丨...`、`记者手记丨...`、`中国摩托加速...`）时，最终归一化会丢弃该段，改用来源摘要/原文正文重写 `内容`。
- 正文兜底重写时不再把来源标题片段当作事实句写入 `内容`，并会合并重复出现的片名/书名句。
- 如果评价套用了与新闻无关的模板，例如文化新闻输出 `AI 使用边界/披露义务/版权和信任`，会替换为与原文事实匹配的文化传承评价，或在无法支撑时留空。

- `test_finalize_daily_news_body_removes_recommendation_noise_and_ai_comment_for_culture_news`

## 2026-06-21 3 条草稿实测前质量回归

本轮删除旧草稿并重新生成 3 条每日新闻前，先用实测中暴露出的坏样本做回归修复：

- 标题不再接受“刚好 17-18 字但明显是从原题中间截断”的 LLM 候选。例如 `山东移动泰安分公司圆满完成因你而来` 会重写为 `演唱会通信保障完成`，`手慢无！“苏新消费·品质数码”手机补` 会重写为 `江苏数码消费补贴启动`，`碧芭宝贝所有已检测纸尿裤产品甲酰胺项` 会重写为 `纸尿裤甲酰胺未检出`。
- 正文清洗新增对 `江南时报讯`、`鲁网...日讯`、`下载客户端`、`责任编辑`、`澎湃新闻-The Paper` 等站点页脚/电头噪声的过滤。
- 正文清洗会丢弃引号不成对的断裂句，避免 `“苏新消费·品。` 这类半截片段进入小红书正文。
- 评价模板检测改为去空格匹配，`AI 使用边界/披露义务/版权和信任` 这类不相关模板只有在版权、出版、署名、训练数据、生成式 AI 等事实支撑存在时才允许保留。
- 新增消费品检测、消费补贴、演唱会通信保障的事实型评价兜底；无法支撑评价时允许省略评价段内容。
- 每日新闻质量闸门现在强制要求最终正文具备 `原文标题/内容/日期/来源` 四个必要字段；如果 LLM 只返回标题、日期和来源，缺少 `内容`，会被判定为 `missing_body_fields` 并跳过候选。
- 澎湃新闻页面的 `报料热线/报料邮箱/ICP备案/许可证/扫码下载客户端` 等页脚信息会在原文清洗阶段截断，不再进入 `内容`。
- 微信原生 AI 助手这类产品新闻不再套用版权/披露义务模板，改为围绕功能边界、用户授权、支付安全和可控性进行客观评价。
