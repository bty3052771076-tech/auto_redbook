# 信源可靠性与 GUI 编辑台优化（2026-07-11）

## 目标

本次调整解决两类问题：

1. `每日新闻` 与 `每日AI讯息` 在网络异常、旧链接失效或信息不够新时，能说明具体信源状态，而不是只给出“素材不足”。
2. GUI 提供一个可操作的信源状态中心，创作者可以在生成前检查覆盖度、发布时间和错误原因。

本次检查和信源同步均为只读操作：不会调用 LLM、不会生成图片、不会创建或上传小红书草稿。

## 每日新闻信源链路

自动抓取按以下顺序回退：

1. 已配置的 NewsAPI、GNews、聚合接口。
2. Google News RSS。
3. BBC RSS。
4. HotNews 热度补充。

每个提供商都会记录原始条目数、带发布时间条目数、带原文 URL 条目数、耗时和错误。无日期的条目不会跨过发布时间门禁进入草稿候选池。

当某一提供商发生超时、网络错误、HTTP 错误、认证错误、空结果或无日期结果时，会写入短暂冷却记录；自动模式在冷却期内直接跳过它并继续尝试下一来源。显式设置 `NEWS_PROVIDER` 时不受该冷却跳过规则影响，便于诊断指定来源。

## 每日 AI 讯息信源链路

AI 讯息按可信度和成本分层：

1. 官方 RSS、GitHub Release 等可追溯动态流。
2. 当官方动态流不足时，补充官方新闻页、产品页和实验室博客。
3. 仍不足时使用社交与搜索补充。
4. Hugging Face 等聚合站只作为最后兜底。

同一层的来源采用有上限的并发抓取。Windows 环境优先使用系统 `curl.exe`，同时设置连接、总时长、重定向和响应体大小限制；其他环境保留 `urllib` 回退。这样单个慢站不会把整批采集卡住。

采集状态包括：

| 状态 | 含义 |
| --- | --- |
| `success` | 已获得可追溯、带发布时间的有效条目。 |
| `empty` | 页面可访问，但没有可解析条目。 |
| `missing_date` | 有条目，但没有可用发布时间，不能进入时效筛选。 |
| `stale` | 有发布日期，但不在本次回溯窗口内。 |
| `timeout` / `transport_error` / `http_error` | 抓取失败；详情保留在错误字段。 |
| `skipped_cooldown` | 同一来源近期已失败，本轮自动跳过。 |

已将失效的旧 RSS 地址替换为当前官方页面：[Anthropic News](https://www.anthropic.com/news)、[Meta AI Blog](https://ai.meta.com/blog) 和 [Microsoft Blog](https://blogs.microsoft.com/)。页面本身没有三天内内容时会显示 `stale`，这与网络抓取失败区分开来。

## 本地快照与诊断

每次真实的自动生成链路都会更新以下本地快照：

```text
data/source_health/daily_news.json
data/source_health/ai_digest.json
```

快照只保存公开信源 URL、检查时间、覆盖度、耗时和错误摘要；不保存 API Key、草稿正文或浏览器 Cookie。`data/` 已被 Git 忽略。

可单独执行只读检查：

```powershell
# 同时检查两类信源
.\.venv\Scripts\python.exe -m apps.cli check-sources --collection all

# 带提示词检查每日新闻来源
.\.venv\Scripts\python.exe -m apps.cli check-sources `
  --collection daily_news `
  --prompt "世界杯" `
  --max-age-days 3

# 只检查每日 AI 讯息，使用三天新鲜度窗口
.\.venv\Scripts\python.exe -m apps.cli check-sources `
  --collection ai_digest `
  --max-age-days 3
```

## GUI：信源中心

GUI 新增顶层 `信源中心` 页面，位于“自动发帖”之后。它包含：

- `检查信源`：运行只读 CLI 检查并刷新快照。
- `刷新本地状态`：不访问网络，只重新读取已有快照。
- 范围筛选、关键词筛选、排序和升降序切换。
- 来源层级、状态、有效覆盖度、耗时、检查时间的紧凑表格。
- 选中行后展示原始 URL、HTTP 状态与错误摘要；仅在点击“打开来源”时才用默认浏览器打开链接。

界面颜色使用深墨色文字、青绿色操作色，并以绿/琥珀/红色区分可用、受限和失败状态。状态表格采用固定列和水平扩展空间，避免长来源名压缩关键覆盖度信息。

## 可配置参数

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `AI_DIGEST_SOURCE_TIMEOUT_S` | `8` | 单个 AI 信源的抓取总时限（3–30 秒）。 |
| `AI_DIGEST_SOURCE_CONCURRENCY` | `4` | 同层 AI 信源并发数（1–12）。 |
| `AI_DIGEST_BATCH_TIMEOUT_S` | `45` | 单层 AI 信源批量等待上限（5–120 秒）。 |
| `AI_DIGEST_SOURCE_COOLDOWN_S` | `300` | AI 信源失败后的自动跳过时间。 |
| `NEWS_SOURCE_COOLDOWN_S` | `300` | 每日新闻提供商失败后的自动跳过时间。 |

需要临时定位某来源时，可以降低并发或明确设置 `NEWS_PROVIDER`；日常生成保持默认值即可。

## 实测与回归

2026-07-11 的只读实测：

- `check-sources --collection daily_news --prompt "World Cup"`：已配置 NewsAPI 返回 20 条带发布时间、带原文 URL 的候选，来源耗时约 16.6 秒。
- 限定 OpenAI 与 Mistral 官方流的 AI 检查：两来源并发完成，耗时约 4.9 秒，均有可追溯日期和链接。
- Anthropic 与 Microsoft 的当前官方页面可成功解析英文日期；在三天窗口内没有新内容时按 `stale` 记录，而不是误报抓取错误。

覆盖源模型、冷却、日期门禁、分层回退、CLI 和 GUI 辅助函数的回归测试已加入。发布前仍应执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q apps src tests
git diff --check
```
