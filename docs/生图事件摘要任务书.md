# 生图事件摘要任务书（LLM 生成「事件描述」用于文生图）

## 1. 背景
当前工作流在「每日新闻」场景下会把较长的正文/关键词传入文生图模型（如 `wan2.7-image`、`wan2.7-image-pro` 或旧的 Qwen-Image 模型）生成配图。即便加入负面提示词（negative prompt），仍可能出现：

- 画面自带文字（字幕/海报排版/路牌文字/屏幕 UI 等）
- 画面呈现“新闻报道感”（新闻海报、采访镜头、演播室、麦克风、记者等），而不是新闻事件本身

原因之一是：输入中含有大量“新闻/报道/来源/点评”等语义与结构，容易把模型引导到“媒体呈现”而非“事件呈现”。

## 2. 目标
1) 当 LLM 为每日新闻生成「新闻内容 + 我的点评」时，额外输出一个 **`image_event`** 字段（约 30 字），只描述事件本身：
   - 仅包含主体/动作/对象/场景线索
   - 不含评价，不含“新闻/报道/采访/来源/链接/时间/记者/媒体”等词
2) 图片生成阶段仅使用 `image_event` 作为主要语义输入（避免“报道感”），以降低生成文字与海报式构图的概率。
3) 将 `image_event` 落盘到 `post.platform.news.image_event`（便于追溯与调参）。

## 3. 非目标
- 不保证 100% 杜绝文字（模型固有概率仍存在）；本任务优先减少“新闻海报/采访感 + 文字”的发生率。
- 不做 OCR 检测与自动重生成闭环（后续可扩展）。
- 不改变小红书保存草稿流程（仅优化生图输入）。

## 4. 设计与实现
### 4.1 LLM 输出扩展
- 在 LLM 结构化输出 JSON 中新增字段：
  - `image_event`: string，建议 20-40 个中文字符（约 30 字）
- 「每日新闻」提示词中加入硬性要求：
  - `image_event` 必须只描述事件，不出现任何“报道/新闻”语义词

### 4.2 落盘与引用
- 在 `create_post` 的每日新闻流程中：
  - 将 `draft["image_event"]` 进行清洗/截断后写入 `post.platform.news.image_event`
- 在图片生成阶段：
  - `_preferred_image_hint()` 优先返回 `post.platform.news.image_event`
  - `auto_image` 构造生图 prompt 时以该短事件描述作为主题输入，减少正文片段的干扰

### 4.3 失败兜底
- 若 `image_event` 缺失或为空：
  - 使用新闻标题（去除“每日新闻｜”等前缀）作为兜底
  - 仍保持“不告诉模型这是新闻”的提示词框架

## 5. 验收标准
1) 执行 `auto --title "每日新闻"`（无本地图片、`IMAGE_PROVIDER=aliyun`、`ALIYUN_IMAGE_MODEL=wan2.7-image` 或设置 `ALIYUN_IMAGE_MODELS`）时：
   - `post.json` 中存在 `platform.news.image_event` 且长度合理（约 20-40 字）
   - 生图提示词不包含“新闻/报道/来源/采访”等媒体语义（以 `image_event` 为主）
2) 相比改动前，生成图片出现“海报/采访/演播室 + 文字”的概率明显降低（人工抽检即可）。

## 6. 测试计划
- 单元测试：
  - `image_event` 清洗/截断逻辑（去除“每日新闻｜/新闻/报道/来源”等）
  - `_preferred_image_hint()` 选择优先级：`image_event` > picked.title/desc > fallback
- 手动验证：
  - 连续运行 2-3 次 `auto --count 3`，对比生成图是否更像“事件插画”，并检查是否仍频繁带字
