# 发布数据同步与运行记录

本文记录 2026-06-27 新增的两类本地分析能力：已发布稿件互动数据同步、生成/上传运行记录。

## 1. 已发布稿件互动数据同步

用途：从小红书创作服务平台读取已发布笔记的点赞、评论、收藏，用于分析下一次新闻选题方向。

终端命令：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 50 --login-hold 600 --wait-timeout 600
```

已确认工作区 Chrome profile 登录后，可无界面同步：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 50 --headless --login-hold 0 --wait-timeout 600
```

GUI 使用：

1. 打开 `AutoRedbookGUI-Launcher.exe`。
2. 进入 `已发布数据` 页签。
3. 设置 `limit`、是否 `无界面同步`、登录等待和页面等待。
4. 点击 `更新已发布数据：点赞 / 评论 / 收藏`。

本地保存位置：

- `data/analytics/published_metrics.csv`：表格格式，适合 Excel/WPS 分析。
- `data/analytics/published_metrics.jsonl`：结构化记录，保留原始文本片段和 URL。

如果后台页面路径变化：

- 当前默认优先访问 `https://creator.xiaohongshu.com/new/note-manager`。
- 在 GUI 的 `配置` 页填写 `XHS_PUBLISHED_URL`。
- 或在 PowerShell 中设置：

```powershell
$env:XHS_PUBLISHED_URL="https://creator.xiaohongshu.com/..."
```

## 2. 运行记录

用途：记录每次 `create` / `auto` 的生成与上传结果，包含条数、模型、图片源、新闻源和错误信息。

本地保存位置：

- `data/runs/run_records.csv`
- `data/runs/run_records.jsonl`

核心字段：

- `command`：`create` 或 `auto`
- `requested_count`：请求生成条数
- `generated_count`：实际生成条数
- `uploaded_count`：成功保存到小红书草稿箱条数
- `failed_count`：失败条数
- `llm_provider` / `llm_models`
- `image_provider` / `image_models`
- `news_provider`
- `post_ids`
- `errors`

## 3. 批量生成部分成功保护

当 `auto --title "每日新闻" --count N` 批量生成时，如果中途发生额度不足、候选不足、质量闸门跳过过多或生图失败，流程不再直接丢弃已生成内容。

当前行为：

- 已经生成并落盘的草稿会继续进入上传流程。
- 终端会输出 `partial daily news`。
- 最后输出摘要，例如：

```text
summary: generated=2 uploaded=2 failed=1 skipped_invalid=0 upload_failed=0 requested=3
```

这表示请求 3 条，生成并上传 2 条，失败 1 条。

## 4. GUI 启动空终端修复

`AutoRedbookGUI-Launcher.exe` 现在只使用 `.venv\Scripts\pythonw.exe -m apps.gui` 启动 GUI，不再回退到 `python.exe`。

`Start-GUI.cmd` 背后的 `scripts/start_gui.ps1` 也会优先通过 `pythonw.exe` + `Start-Process -WindowStyle Hidden` 隐藏启动。

如果缺少 `pythonw.exe`，请重新创建或修复当前工作区 `.venv`，不要把依赖安装到 C 盘。
