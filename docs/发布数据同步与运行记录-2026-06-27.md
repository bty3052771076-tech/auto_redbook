# 发布数据同步与运行记录

本文记录 2026-06-27 新增的两类本地分析能力：已发布稿件互动数据同步、生成/上传运行记录。

## 1. 已发布稿件互动数据同步

用途：从小红书创作服务平台读取已发布笔记的点赞、评论、收藏，用于分析下一次新闻选题方向。

终端命令：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 0 --login-hold 600
```

已确认工作区 Chrome profile 登录后，可无界面同步：

```powershell
.\.venv\Scripts\python.exe -m apps.cli update-metrics --limit 0 --headless --login-hold 0
```

GUI 使用：

1. 打开 `AutoRedbookGUI-Launcher.exe`。
2. 进入 `已发布数据` 页签。
3. 设置 `limit`、是否 `无界面同步`、登录等待，以及是否要求严格全量。
4. 点击 `更新已发布数据：点赞 / 评论 / 收藏`。
5. 同步成功后，下方 `本地已发布数据表` 会自动刷新；也可以点击 `刷新本地表格` 手动读取本地最新表。
6. 表格列包含 `标题`、`发布时间`、`浏览`、`点赞`、`评论`、`收藏`、`分享`、`同步时间`。点击任意列头可切换升序/降序排序，常用分析入口是按 `点赞`、`评论`、`收藏` 或 `浏览` 降序查看高互动内容。
7. 点击 `分析发布方向`，软件会基于本地互动表输出后续新闻方向建议。当前版本使用本地规则分析器作为兜底算法，不会自动调用外部 LLM，也不会自动执行上传；后续可扩展为外部 LLM 分析，本地规则结果可作为兜底和校验。

本地保存位置：

- `data/analytics/published_metrics_latest.csv`：本次同步快照去重后的最新表，适合 Excel/WPS 直接分析下一次发布方向；不会从历史 JSONL 中补入旧快照记录。
- `data/analytics/published_metrics.csv`：每次同步的 CSV 快照，会追加历史记录。
- `data/analytics/published_metrics.jsonl`：结构化快照记录，保留原始文本片段和 URL。

如果后台页面路径变化：

- 当前默认优先访问 `https://creator.xiaohongshu.com/new/note-manager`。
- 旧版 `/creator/notes` 和发布编辑页不再作为默认回退入口，避免平台返回“你访问的页面不见了”时被误判为已发布列表。
- 在 GUI 的 `配置` 页填写 `XHS_PUBLISHED_URL`。
- 或在 PowerShell 中设置：

```powershell
$env:XHS_PUBLISHED_URL="https://creator.xiaohongshu.com/..."
```

全量同步相关可调参数：

- `XHS_METRICS_MAX_ITEMS`：单次 DOM 收集上限，默认 `1000`。
- `XHS_METRICS_MAX_SCROLLS`：页面滚动轮数上限，默认 `240`。已发布稿件很多或后台加载慢时可调大。
- `XHS_METRICS_STAGNANT_ROUNDS`：连续没有新增数据时的停滞容忍轮数，默认 `90`，最低 `18`。全量同步时可调大以等待慢加载。

页面关闭逻辑：

- GUI 不再要求为“更新已发布数据”设置页面等待时间。
- 底层仍有单步 UI 等待保护，避免某个页面元素永久卡住；它不是全量同步的总任务时限。
- 浏览器页面会在采够目标数量、达到 `--limit`，或达到滚动/停滞判定并返回完整或不完整结果后关闭。

2026-07-02 起，默认逻辑是严格全量：

- `--limit 0`：必须采集到页面显示的 `全部 N`，例如页面显示 `全部 322`，最终必须采集 `322` 条才会写入 `published_metrics_latest.csv`。
- `--limit N`：必须采集到请求的 `N` 条；若页面总数小于 `N`，则以页面总数为准。
- 如果只采到部分数据，例如 `317/322`，CLI 会报 `incomplete published metrics` 并拒绝覆盖 latest。
- 如果页面目标数未知，`--limit 0` 不再把“已采集数量”当成目标数，也会视为本轮未完整。
- 只有显式传入 `--allow-partial` 时，才会把部分结果保存为最新表；该选项只建议用于调试或人工确认缺口可接受的场景。

## 1.1. 本地发布方向分析

用途：根据 `published_metrics_latest.csv` 中的已发布表现，给出下一批新闻的发布方向比例、分类表现和代表标题。当前实现是本地规则兜底算法；后续如果接入外部 LLM，可在此结果基础上进一步做策略解释、选题组合和标题建议。

终端命令：

```powershell
.\.venv\Scripts\python.exe -m apps.cli analyze-metrics
```

如需保存 Markdown 报告：

```powershell
.\.venv\Scripts\python.exe -m apps.cli analyze-metrics --save
```

保存位置：

- `data/analytics/published_metrics_analysis.md`

当前分析逻辑：

- 使用本地去重后的最新表，不使用历史快照重复计数。
- 统计浏览、点赞、评论、收藏、分享和有互动占比。
- 按标题关键词归类为 `国际冲突/外交安全`、`硬科技/芯片/AI`、`社会民生/公共事件`、`争议文化/体育/品牌`、`财经产业/公司`、`健康科学/环境`、`其他`。
- 综合平均浏览、平均互动、有互动占比和样本数量，生成建议发布比例。
- 样本少或互动少时会标注 `弱信号`，提醒只作为测试方向。

## 2. 运行记录

用途：记录每次 `auto` 的生成与上传结果，包含条数、模型、图片源、新闻源和错误信息。历史数据中可能仍存在 2026-07-01 前公开 `create` 命令写入的记录。

本地保存位置：

- `data/runs/run_records.csv`
- `data/runs/run_records.jsonl`

核心字段：

- `command`：当前公开入口为 `auto`；历史记录可能为 `create`
- `requested_count`：请求生成条数
- `generated_count`：实际生成条数
- `uploaded_count`：成功保存到小红书草稿箱条数
- `failed_count`：失败条数
- `llm_provider` / `llm_models`
- `image_provider` / `image_models`
- `news_provider`
- `post_ids`
- `errors`

## 3. 批量生成部分成功保护

当 `auto --title "每日新闻" --count N` 批量生成时，如果中途发生额度不足、候选不足、质量闸门跳过过多或生图失败，流程不再直接丢弃已生成内容。

当前行为：

- 已经生成并落盘的草稿会继续进入上传流程。
- 终端会输出 `partial daily news`。
- 最后输出摘要，例如：

```text
summary: generated=2 uploaded=2 failed=1 skipped_invalid=0 upload_failed=0 requested=3
```

这表示请求 3 条，生成并上传 2 条，失败 1 条。

## 4. GUI 启动空终端修复

`AutoRedbookGUI-Launcher.exe` 现在只使用 `.venv\Scripts\pythonw.exe -m apps.gui` 启动 GUI，不再回退到 `python.exe`。

`Start-GUI.cmd` 背后的 `scripts/start_gui.ps1` 也会优先通过 `pythonw.exe` + `Start-Process -WindowStyle Hidden` 隐藏启动。

如果缺少 `pythonw.exe`，请重新创建或修复当前工作区 `.venv`，不要把依赖安装到 C 盘。
