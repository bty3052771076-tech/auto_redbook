# 图形界面工作流增强任务书（默认值 + 仅上传）

## 1. 背景
当前项目已提供 Tkinter 图形界面（`apps/gui.py`），用于在窗口中配置环境变量并一键执行常用 CLI 命令（`auto` / `create` / `delete-drafts`）。
在实际使用中仍存在两个痛点：
1) GUI 文本框默认值偏少，首次打开需要手工填很多项；
2) “仅生成（create）”之后缺少“仅上传（run）”入口，无法在 GUI 内形成“生成 → 人工检查 → 上传保存草稿”的完整工作流。

同时，GUI 允许保存本机配置到 `.env.gui`，其中可能包含 API Key，必须确保该文件不会被提交/上传到 GitHub。

## 2. 目标
1) 为 GUI 的**各类文本输入框**补充“开箱即用”的默认值（不影响用户自定义覆盖）。
2) 强化“API Key 不上传”保障：
   - `.env.gui` 仅作为本机文件使用，默认被 Git 忽略；
   - 保存/日志等交互不泄露敏感信息。
3) 新增“仅上传（run）”能力，并与“仅生成（create）”组成完整工作流：
   - 允许输入/选择 `post_id`；
   - 支持 `approve`（可选）与 `run`（仅上传）两步操作。

## 3. 非目标
- 不将 GUI 改为复杂框架（保持 Tkinter，减少依赖）。
- 不实现“发布”能力（仍然只保存草稿）。
- 不将 exe 做成完全独立运行（仍以仓库 `.venv` 为运行时，exe 只是启动器）。

## 4. 设计与实现

### 4.1 默认值策略
#### 4.1.1 配置页（环境变量）
- `ALIYUN_LLM_MODEL`：默认 `qwen3.7-plus`
- `ALIYUN_LLM_BASE_URL`：默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`
- `IMAGE_PROVIDER`：默认 `aliyun`
- `ALIYUN_IMAGE_MODELS`：默认 `wan2.7-image`（可按需改为 `wan2.7-image,wan2.7-image-pro` 等多模型候选）
- `ALIYUN_IMAGE_SIZE`：默认 `1104*1472`（3:4，适配小红书竖图）
- `ALIYUN_IMAGE_NEGATIVE_PROMPT`：默认加入“禁止文字/水印/Logo”等约束（降低图片带字概率）
- `NEWS_CHINA_RATIO`：默认 `0.6`（中国新闻：海外新闻 ≈ 6:4）
- `NEWS_CHINA_BONUS`：默认 `0.15`
- API Key 类字段（如 `DASHSCOPE_API_KEY` / `NEWS_API_KEY` / `PEXELS_API_KEY`）：默认保持空（不替用户写入）

#### 4.1.2 工作流页（命令参数）
- `auto/create`：
  - 标题默认：`每日新闻`（便于直接验证“每日新闻”工作流；用户可修改）
  - 素材 glob 默认：`assets/pics/*`
  - 数量默认：`1`
  - `login-hold` 默认：`600`
  - `wait-timeout` 默认：`600`
- `run（仅上传）`：
  - 默认从 `data/posts/` 自动选择最近的 `post_id`（若存在）
  - `login-hold` / `wait-timeout` 默认同上

### 4.2 API Key 不上传保障
- `.env.gui` 文件保持在仓库根目录，仅用于本机；在 `.gitignore` 中**显式忽略**（并保留现有 `.env.*` 兜底规则）。
- `.env.gui` 的保存逻辑：
  - 仅保存用户填写的非空键值；
  - 文件头部写入醒目注释：`DO NOT commit`；
  - GUI 日志不打印 key 的明文（仅提示“已保存路径”）。

### 4.3 新增“仅上传（run）”工作流
在 GUI 新增一个页签（或区域）用于：
1) 选择/填写 `post_id`（可从本地 `data/posts/` 自动列出最近记录，支持刷新）。
2) 运行 `approve <post_id>`（可选，用于通过校验并标记已审核）。
3) 运行 `run <post_id>`（仅上传并保存草稿）：
   - 支持 `--assets-glob`（可选；为空则使用 `data/posts/<id>/assets/*` 或 post 内记录）
   - 支持 `--dry-run` / `--force` / `--login-hold` / `--wait-timeout`

> 说明：CLI 的 `run` 默认要求 `post.status=approved`，因此 GUI 至少需要提供 `approve` 入口，避免用户卡在“未审核无法上传”的错误上。

## 5. 验收标准
1) GUI 启动后，各文本输入框均具备合理默认值（API Key 字段保持空）。
2) `.env.gui` 在 Git 层面默认不会被追踪/提交（`.gitignore` 明确包含），且保存/日志不会泄露 Key。
3) 新增的 `approve` / `run（仅上传）` 在 GUI 内可正常构造命令并执行。
4) 单元测试覆盖新增的 CLI 参数构造逻辑（至少覆盖 `approve` / `run`）。

## 6. 测试计划
- 单元测试：
  - `build_cli_args("approve")` / `build_cli_args("run")` 参数构造
  - `.env.gui` 读写不破坏格式、能正确处理引号/空白
- 手动测试：
  1) GUI 启动检查默认值
  2) `create` 生成 `post_id`
  3) `approve` 标记通过
  4) `run` 上传并保存草稿（或 `dry-run` 验证打开页面与取证）
