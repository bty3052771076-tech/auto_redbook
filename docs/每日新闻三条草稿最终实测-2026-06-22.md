# 每日新闻三条草稿最终实测 - 2026-06-22

## 背景

本轮目标是删除小红书创作者中心旧草稿，修复每日新闻标题、正文、评价与站点噪声问题，并重新生成 3 条带 AI 配图的图文草稿。

## 本轮修复点

- 标题压缩新增大湾区、科幻论坛、韩国科技等真实坏样本规则，避免 17-18 字硬截断，例如 `依托城市群区域协同一体化发展粤港澳大`。
- 正文清洗新增 HTML 残留过滤，拦截 `<p>`、`<img>`、`referrerpolicy`、`width=` 等聚合详情页脏数据。
- 正文清洗新增站点侧栏噪声过滤，拦截 `打开微信`、`扫一扫`、`热文排行`、`财经日历`、`今日要点`、`21早新闻`、`查看全部 -->` 等。
- 评价逻辑收窄 AI/版权模板触发条件，`AI 使用边界/披露义务/版权和信任` 只允许在出版、版权、署名、生成式 AI 等事实支撑存在时出现。
- 新增大湾区科创、韩国科技跨境资金、农业夏播等事实型评价兜底，并增加最终正文的 `comment_mismatch` 质量门禁。
- 上传前质量门禁新增 `body_html_artifacts`、`body_site_noise`、`comment_mismatch`，不合格候选会被跳过或重写。

## 新闻源实测状态

- Juhe 聚合数据：实时测试返回 `stage=获取新闻`，原因是 `超过每日可允许请求次数`。
- GNews：实时测试返回 HTTP 429。
- NewsAPI：本机网络到 `newsapi.org` 连接超时。
- 最终端到端测试：使用本地缓存的 GNews 候选文件 `data/news_candidates/gnews_filtered_20260622.json` 作为 `NEWS_PROVIDER=file` 输入，不包含任何 API key。
- 因前一轮坏草稿已写入本地历史 URL 查重记录，但远端草稿已删除，本轮复测临时设置 `NEWS_HISTORY_DEDUPE=0`，用于验证同一批候选经过修复后能正确生成和上传。
