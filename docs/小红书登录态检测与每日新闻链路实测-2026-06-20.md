# 小红书登录态检测与每日新闻链路实测

日期：2026-06-20

## 修复内容

本次修复解决了 `--login-hold` 固定等待的问题。旧逻辑只要设置 `login-hold`，进入小红书创作平台后就会无条件等待完整秒数，即使浏览器 profile 已经登录也会卡住。

现在行为如下：

- 已进入小红书发布编辑器：立即继续上传链路，不再等待完整 `login-hold`。
- 检测到登录页：有界面模式下最多等待 `login-hold` 秒，等待期间持续检测是否登录完成。
- 无界面模式下检测到未登录：快速失败并提示先用 GUI 的“登录/检查Profile”登录。
- 终端会输出 `[xhs-upload] login_check`，显示当前页面状态和是否进入 ready。

## 质量补强

完整链路实测时发现两个额外问题，已一并修复：

- 英文/外文标题关键词匹配从“子串匹配”改为“英文词边界匹配”，避免法语 `importe` 被误判为英文 `import`，进而错误生成“外贸数据出现变化”。
- 每日新闻候选过滤增加 PyPI/GitHub/NPM 包发布、`Watch:` 视频片段、`News in brief` 简讯列表等低质量候选过滤。
- 泛化标题和泛化正文会被质量闸门拦截，不再进入 AI 生图和上传。
- 当 LLM 输出过泛时，系统会对事实充足的候选使用事实型中文兜底正文，例如海水电池、北约/美军欧洲部署、作家使用 AI 等场景。

## 真实链路结果

第一次真实链路使用 NewsAPI 成功生成并上传了 2 条草稿，但人工核验发现标题/正文过泛：

- `外贸数据出现变化`
- `AI议题出现进展`

这两条是本次测试产生的低质量草稿，已通过删除功能删除：

```powershell
.\.venv\Scripts\python.exe -m apps.cli delete-drafts --draft-type image --limit 2 --yes --headless --login-hold 600 --wait-timeout 300
```

结果：`deleted 2/12 drafts (image)`。

随后 NewsAPI 和 GDELT 均返回 429 限流。为完成“生成 -> AI 配图 -> 上传小红书草稿”的链路验证，本次使用刚才 NewsAPI 返回并已落盘的候选缓存：

```powershell
$env:NEWS_PROVIDER="file"
$env:NEWS_CANDIDATES_FILE="data/news_candidates_api_cache_2026-06-20.json"
```

最终成功生成并上传 2 条每日新闻草稿：

- `c30ccbd535fd4c19a96c0410be483b3d`：`海水电池技术突破`
- `eef16f64e55847e58ed98e43f6a0b370`：`美军欧洲部署审查`

两条均满足：

- 状态：`saved_as_draft`
- 小红书草稿箱校验：`verified_title=True cover_ready=True`
- 图片：阿里云 AI 生图，`wan2.7-image`
- 正文：无 URL，包含发布时间和来源
- 登录检测：`login_check: state=ready`

最终草稿箱 dry-run 顶部验证：

```text
type=image total=12
- 美军欧洲部署审查 保存于2026-06-20 15:11:03
- 海水电池技术突破 保存于2026-06-20 15:09:58
```

## 说明

`login-hold` 现在是“最长登录等待时间”，不是固定暂停时间。已登录时即使设置 `--login-hold 600`，也会在检测到发布编辑器可用后立即继续。
