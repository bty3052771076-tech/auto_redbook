# 每日新闻 RSS 来源与日期门禁修复（2026-07-10）

## 背景

`每日新闻` 在候选新闻阶段曾出现“14 天内仍为 0 条”的报错。排查确认，问题不在 LLM、生图或小红书上传：当有 Key 的新闻接口暂时失败时，旧的最终回退源 HotNews 可返回热榜条目，但这些条目没有可解析的发布时间。严格日期筛选会正确丢弃无日期条目，因而候选池变成 0。

本次不放宽日期要求。没有可靠发布时间的新闻不能进入按日期生成的草稿。

## 来源优先级

自动模式的在线来源顺序调整为：

1. 已配置的 `newsapi`、`gnews`、`juhe`。
2. Google News RSS 搜索源 `google_rss`，无需 API Key。
3. BBC RSS 分类源 `bbc_rss`，无需 API Key。
4. HotNews 热榜，作为最后的热度补充；无发布时间的条目仍会被日期门禁排除。

人工提供的单条新闻材料或候选材料文件继续优先于在线抓取，不受本次变更影响。

## Google News RSS

Google RSS 会以提示词和已知英文同义查询抓取新闻，保留发布者、原始链接和 RFC 822 `pubDate`。发布时间会统一转换为 ISO 8601，供北京时间窗口筛选。

已补充常见中英文检索映射，例如：

- `世界杯` -> `world cup`
- `足球` -> `football` / `soccer`
- `公司政策` -> `policy` / `business` / `company`
- `市场变化` -> `market` / `prices` / `stock`

可在本地显式测试该来源：

```powershell
$env:NEWS_PROVIDER = "google_rss"
.\.venv\Scripts\python.exe -m apps.cli auto --title "每日新闻" --prompt "世界杯" --count 1
```

## BBC RSS

BBC RSS 按提示词选择分类，适合在搜索源不可用时提供有明确发布时间的补充：

- 体育、足球、世界杯：`sport`
- 财经、公司、市场：`business`
- 科技、AI：`technology`
- 其他国际时事：`world`

可在本地显式测试：

```powershell
$env:NEWS_PROVIDER = "bbc_rss"
.\.venv\Scripts\python.exe -m apps.cli auto --title "每日新闻" --prompt "世界杯" --count 1
```

## 日期与异常处理

- 默认仍按北京时间依次尝试 3、7、14 天窗口；指定 `--lookback-days N` 时仅使用 N 天窗口。
- RSS 的 `pubDate` 会解析后再执行日期筛选；无法解析日期的项目不会进入草稿候选池。
- 一个提供商遇到认证、网络或超时异常后，会立即尝试下一个提供商，不再对同一失败提供商反复请求多个同义查询。
- 运行记录中的 `provider_attempts`、`provider_errors`、`source_meta` 和候选源 URL 可用于追溯来源。

## 验证记录

2026-07-10 在不调用 LLM、不生图、不上传草稿的只读候选新闻测试中：

- 强制 `google_rss` 查询 `世界杯`：抓取 100 条，其中 34 条位于北京时间三天窗口内，33 条通过相关性筛选。
- 强制 `bbc_rss` 查询 `世界杯`：体育 RSS 返回 75 条，其中 64 条位于三天窗口内，16 条通过相关性筛选。
- 自动模式：当前 NewsAPI 可用时优先成功，抓取 100 条，其中 15 条位于三天窗口内，12 条通过相关性筛选；当它再次失败时会自动继续尝试 Google RSS、BBC RSS 和最后的 HotNews。

相应回归测试覆盖：中文提示词与英文标题匹配、RSS 发布时间和发布者保留、世界杯分类选择、Google RSS URL 构造、自动回退顺序，以及提供商异常后不重复请求同义查询。
