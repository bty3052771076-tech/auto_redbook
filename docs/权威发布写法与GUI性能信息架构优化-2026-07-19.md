# 权威发布写法与 GUI 性能信息架构优化（2026-07-19）

## 目标

1. 用公开、权威的新闻发布规范提炼 `每日新闻` 的内部写作约束，提升事实边界、时间边界和可追溯性；不将任何单篇新闻、机构事件、人物或数据写入模板。
2. 缓解本地草稿较多时 GUI 的启动和操作卡顿，并让每个页面的名称、状态和操作与实际功能一致。

## 权威依据与提炼原则

本轮只参考公开规范的通用要求，不复制任何具体新闻内容：

- [国家网信办《互联网新闻信息服务管理规定》](https://www.cac.gov.cn/2017-05/02/c_1120902760.htm)：转载信息应保留来源和可追溯性，不得歪曲标题原意和内容。
- [国家新闻出版署关于加强新闻采编管理的要求](https://www.nppa.gov.cn/xxgk/fdzdgknr/zcfg_210/gfxwj_215/201708/t20170829_4693.html)：采编应履行核实和审核要求，标题应文题相符，避免夸大失实。
- [国家新闻出版署《新闻记者证管理办法》](https://www.nppa.gov.cn/xxgk/fdzdgknr/zcfg_210/bmgz_213/202112/P020221115768870709623.pdf)：新闻报道应真实、全面、客观、公正。
- [国家广播电视总局新闻作品推优标准](https://www.nrta.gov.cn/art/2025/7/3/art_113_71051.html)：强调内容真实、表述准确、逻辑严谨和消息的简明完整。
- [国家网信办《关于加强“自媒体”管理的通知》](https://www.cac.gov.cn/2023-07/10/c_1690638496047430.htm)：要求显著标注来源，禁止歪曲事实和以旧充新。

内部规则据此要求：

1. 只写已核实、可追溯、与主题直接相关的事实；材料无法支持时不以猜测补足。
2. 标题与正文的已核事实范围一致，采用重要性递减的短消息结构。
3. 明确区分事实、来源表述、计划安排和分析判断；单方信息须归因，推断须保留不确定性。
4. 分开处理发生时间、发布时点和当前状态，避免把旧信息写成新进展。
5. 评价只在材料支持时说明已知影响与待观察变量，不写投资建议、立场表达或情绪化措辞。

## 实现

### 每日新闻内部规则

- `src/workflow/create_post.py` 的 `_daily_news_professional_reporting_instruction()` 扩展为“权威发布写法”。
- 规则为泛化约束，不含任何新闻标题、机构、人名、时间、数字或事件；实际事实仍只从运行时注入的候选新闻材料读取。
- 原有简体中文、来源可追溯、正文不输出 URL 和质量门禁保持不变。

### 生成草稿页面

自动发帖页保留原入口名称，页内明确为“生成草稿”，并说明其只会保存到创作者中心草稿箱，不会正式发布。页面按真实执行顺序拆为：

1. `内容与来源`：栏目、关键词、评价视角、数量和回溯天数。
2. `材料模式`：`实时检索`、`单条材料（固定生成 1 条）`、`多条材料（继续筛选）` 三选一；只显示当前生效的文件输入，运行时只传对应参数。
3. `本次模型`：LLM 供应商/模型与图片来源/模型。
4. `运行设置` 和 `生成并保存草稿`：状态摘要会显示栏目、材料模式、数量和“仅验证/保存草稿”。

生成成功后会自动请求刷新本地草稿和可发布草稿列表，避免用户需要手动跨页面确认结果。

### 任务监控与性能

- CLI 输出不再逐行直接写入 Tk `Text` 控件。`UiLogBuffer` 在后台收集输出，按 120ms、最多 360 条或约 24KB 的批次插入；日志保留最近约 220KB，避免长期运行后文本控件越来越慢。
- UI 事件轮询从 50ms 调整为 80ms；状态更新仍通过主线程队列执行。
- 额度搜索、信源搜索和额度面板尺寸变化增加约 140ms 的防抖，减少输入过程中的全量重绘。
- 本地草稿列表先按目录修改时间排序，只解析最近请求数量的草稿；不会再为所有历史草稿读取执行记录。
- 可发布草稿列表和最近草稿列表改为后台读取，并以 generation 标记丢弃过期刷新结果，Tk 主线程只渲染最终结果。
- 已发布数据选择某一行时，本地草稿匹配移到后台并缓存，避免点击表格时阻塞界面。
- 任务结束后的刷新回调改为按 `posts`、`publish`、`metrics`、`quota`、`sources` 去重；忙碌时点击额度同步不会遗留陈旧刷新回调。

### 其他界面语义修正

- 右侧面板改称“任务监控”，顶部显示当前阶段；切换左侧功能页时，窗口标题区同步显示该页的实际工作内容。
- 发布草稿筛选标签改为“上传日期（北京时间）”。`limit=0` 现在真的显示并执行全部匹配草稿，确认数量与实际范围一致；主按钮会显示“预览/发布 N 条草稿”。
- 删除草稿的“执行前确认”在 GUI 内使用确认弹窗，确认后显式传递确认标记，不再依赖没有 stdin 输入通道的后台 CLI 询问。

## 验证

```powershell
.\.venv\Scripts\python.exe -m py_compile apps\gui.py src\workflow\create_post.py
.\.venv\Scripts\python.exe -m pytest tests\test_gui.py -q --disable-warnings --maxfail=1
# 89 passed

.\.venv\Scripts\python.exe -m pytest tests\test_daily_news.py -q -k "professional_reporting_rules_without_news_examples"
```

GUI 测试新增了日志批处理顺序、清空缓存、防抖只执行最新刷新、本地草稿仅解析请求数量等覆盖。未在本轮调用 LLM、生图或小红书上传，因此不会消耗模型额度，也不会创建平台草稿。

本机现有数据的只读测量结果：`list_recent_posts(limit=80)` 为 `0.264s`，`list_publishable_drafts(limit=0)` 为 `0.674s`。两项读取在 GUI 中均放到后台线程，界面线程只接收最终渲染结果。

## 兼容性

- CLI 参数仍支持历史 `--prompt` 别名；GUI 和用户文档继续以“关键词”表达检索输入。
- 单条/多条人工材料的 CLI 行为没有改变，GUI 只是将两种互斥模式显式化。
- `自动发帖` 标签保持不变，避免已有操作习惯和截图指引失效；页面内标题使用“生成草稿”明确其保存范围。
