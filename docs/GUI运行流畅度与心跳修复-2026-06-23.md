# GUI 运行流畅度与心跳修复（2026-06-23）

## 问题

GUI 运行 `auto` / `create` / `run` 时，本质上是在窗口中启动同一套 CLI 命令。旧版 GUI 只有在子进程输出新行或退出时才刷新日志；当任务正在等待新闻 API、LLM、VLM 生图或小红书页面响应时，可能几十秒没有新输出，看起来像“卡住”。

## 修复

- GUI 子进程环境新增 `PYTHONUNBUFFERED=1`，减少 CLI 输出被缓冲导致的延迟。
- `CommandRunner` 改为输出读取线程 + 主循环轮询，避免 stdout 静默时无法更新界面。
- 长任务默认每 20 秒输出一次心跳：

```text
[gui] 仍在运行，已耗时 00:20；当前可能在等待新闻 API、LLM、VLM 生图或小红书页面响应。
```

- GUI 日志区新增状态显示：`空闲` / `运行中` / `正在停止`。
- “停止当前任务”现在会在日志中明确反馈停止请求。
- 已重新生成根目录 `AutoRedbookGUI-Launcher.exe`，该文件仍只是轻量启动器，不安装依赖、不打包密钥。

## 使用建议

- 如果 GUI 显示心跳，通常表示任务仍在等待外部服务，并不是窗口冻结。
- 如果心跳持续很久且没有步骤输出，可点击“停止当前任务”，再改用终端命令复现，以便查看更详细的外部服务错误。
- 首次登录或验证码仍建议使用可视浏览器；确认 profile 已登录后再勾选无界面上传。
