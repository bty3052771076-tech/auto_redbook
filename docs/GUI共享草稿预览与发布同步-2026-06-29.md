# GUI 共享草稿预览与发布同步（2026-06-29）

## 目标

本次调整解决两个问题：

- GUI 右侧改为上下两块：上方 `运行日志`，下方 `草稿预览`。
- 草稿在发布前可能会在小红书创作者中心被修改，因此本地需要同步实际发布后的标题、状态和互动数据。

## GUI 使用方式

右侧区域现在固定承担两个职责：

- 上方 `运行日志`：显示 CLI 子进程输出、阶段进度、退出码。
- 下方 `草稿预览`：显示当前选中稿件的完整可追溯信息。

以下页面会联动右侧草稿预览：

- `草稿处理`：选择本地 post 后，右侧显示本地完整正文、素材、新闻来源、上传状态、发布时间等。
- `发布草稿`：选择可发布草稿后，右侧显示该草稿完整内容；多选时显示第一条，并提示总选择数量。
- `已发布数据`：选择已发布数据行后，优先匹配本地 post 并显示本地全文；如果无法匹配，只显示平台同步到的公开标题、发布时间、点赞、评论、收藏、浏览、分享和链接。

## 发布同步逻辑

### 自动发布时

`publish-drafts` 在点击发布前会尝试读取创作者中心编辑器中的实际标题和正文：

- `platform.publish.actual_title`
- `platform.publish.actual_body`

发布成功后，本地 `post.json` 会标记：

- `status = published`
- `platform.publish.result = published`
- `platform.publish.source = creator_center_draft`
- `platform.publish.published_at = 当前本地记录时间`

### 同步已发布数据时

`update-metrics` 从创作者中心已发布列表抓取平台数据后，会保存 metrics，并反向同步本地 post：

- 优先用小红书笔记 URL 匹配。
- 其次用本地标题匹配。
- 如果发布时已经记录 `actual_title`，也会用实际平台标题匹配。
- 匹配成功后，本地 post 标记为 `published`，并写入 `platform.publish.metrics`。

可同步的互动字段包括：

- `likes`
- `comments`
- `favorites`
- `views`
- `shares`

## 严谨性说明

当前平台已发布列表同步到的是标题、发布时间、互动数据和链接，不保证能获取已发布正文。因此：

- 如果发布由本工具执行，正文以发布前从编辑器读取的 `actual_body` 为准。
- 如果发布在平台手动完成，且本工具没有读取过编辑器正文，则 GUI 会明确显示本地正文或仅显示平台公开数据，不会假装拿到了平台正文。

## 验证

已增加并通过的测试覆盖：

- 共享草稿预览读取完整 `post.json`。
- 已发布数据行按 URL 匹配本地 post。
- 已发布 metrics 反向同步本地 post 为 `published`。
- metrics 可用 `actual_title` 匹配发布前已修改的草稿。
- `publish-drafts` 写回 `actual_title` / `actual_body`。
- Playwright 发布前编辑器快照读取。
