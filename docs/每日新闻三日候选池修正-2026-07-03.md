# 每日新闻三日候选池修正（2026-07-03）

## 背景

`每日新闻` 生成草稿时，用户要求不能出现上个月旧新闻。此前流程在上传数量为 `x` 时直接向新闻源请求 `2x` 条，再过滤三日窗口。如果新闻源前几条偏旧，就会出现三日内候选为空的误判。

## 当前规则

- 最终进入生成的候选仍为 `2x` 条左右。
- 这 `2x` 条必须全部来自北京时间生成日、昨天、前天三日窗口。
- 原始抓取数量不再等于最终候选数量，默认至少多抓 20 条。
- 可用 `NEWS_UPLOAD_RAW_MAX_RECORDS` 或 `NEWS_RAW_MAX_RECORDS` 调整原始抓取数量。

## 执行链路

`src/workflow/create_post.py`：

1. `_daily_news_candidate_fetch_limit(count)` 计算最终候选池目标，固定为 `count * 2`。
2. `_daily_news_raw_candidate_fetch_limit(target_fetch_count)` 计算原始抓取数量，默认 `max(20, target_fetch_count * 5)`，最高 100。
3. `fetch_daily_news_candidates(..., max_records=raw_fetch_count)` 多抓原始候选。
4. `filter_recent_news_items(..., max_age_days=3)` 过滤北京时间三日窗口。
5. 只取三日内的前 `target_fetch_count` 条进入后续筛选和 LLM。

如果三日窗口为空，程序会明确报错并显示日期窗口，不会用旧新闻补位。

## 元数据

`post.platform.news.selection_pool` 会记录：

- `requested_count`
- `target_fetch_count`
- `raw_fetch_count`
- `raw_candidate_count`
- `recent_candidate_count`
- `actual_candidate_count`
- `dropped_out_of_window_count`
- `date_window`

