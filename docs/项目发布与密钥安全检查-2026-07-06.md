- CLI 示例：每日新闻、每日 AI 讯息、单条新闻材料、多条新闻材料、草稿发布、草稿删除、已发布数据同步、模型额度查询。

- 安全说明：`data/`、`.env*`、真实 `docs/*api-key.md`、`.venv/`、`.playwright-browsers/`、`output/`、`logs/` 等只保留在本地。
- 发布前检查：测试、编译、格式检查和密钥扫描命令。

## 可提交内容

- 源码：`apps/`、`src/`、`scripts/`。
- 测试：`tests/`。
- 文档：`README.md`、`docs/*.md`、`docs/plans/*.md`、`docs/*.example.md`。
- 示例图片或文档资产：`docs/assets/` 中用于说明功能的静态资源。

## 不应提交内容

- `data/`：本地帖子、图片、运行记录、浏览器 profile、额度快照、已发布指标。
- `.env`、`.env.*`、`.env.gui`：本地环境变量。
- `docs/*api-key.md`：真实 API Key 文件；仅 `.example.md` 模板可提交。
- `.venv/`、`.playwright-browsers/`：本地运行环境。
- `logs/`、`output/`：调试输出。
- `AGENT.md`、`CODING_PROGRESS.md`：本地协作记录。
- 私钥或证书：`*.pem`、`*.p12`、`*.pfx`、`*.key`。

## 发布前检查流程

1. 查看待提交文件：

```powershell
git status --short
git diff --stat
```

2. 确认 `.gitignore` 已覆盖本地数据和真实 key：

```powershell
git check-ignore -v .env .env.gui data docs/volcengine_api-key.md docs/llm_api-key.md
```

3. 扫描真实 key 常见形态：

```powershell
git grep -l -I -E "sk-[A-Za-z0-9]{20,}|[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}" -- .
```

4. 运行测试和编译：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q apps src tests
git diff --check
```

5. 提交并推送：

```powershell
git add README.md docs src apps tests scripts
git commit -m "docs: update quick start and publish current workflow"
git push origin main
```

- 新增回归测试 `test_auto_news_material_options_do_not_leak_process_environment`，防止材料文件参数再次泄漏为全局 `NEWS_MATERIALS_FILE` / `SINGLE_NEWS_MATERIAL_FILE`。

## 注意事项

- README 中只能出现 `YOUR_...` 这类占位符，不写真实 key。
- 如果 `git grep` 命令返回文件，需要先判断是否只是占位符或测试假值；真实 key 必须移除。
- 如果 `data/` 或浏览器 profile 出现在 `git status` 中，应立即停止提交并检查 `.gitignore`。
- 推送前不要使用 `git add -A` 盲目添加全部文件；应确认新增文件都属于源码、测试或文档。
