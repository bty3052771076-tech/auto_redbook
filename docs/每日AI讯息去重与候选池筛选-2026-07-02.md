# 每日AI讯息去重与候选池筛选

## 背景

实测草稿中出现了同一主题的重复条目，例如 `GeneBench-Pro` 的介绍页和案例页被同时选入。“每日AI讯息”还需要让第一页尽量展示北京时间当日或最新日期的热点 AI 资讯，并优先选择技术类型、模型版本类型动态；观点探讨类内容只能作为补充。

同时，用户需要能判断系统是否遵守“候选不足不硬凑 10 条”的规则，因此正文和 metadata 需要展示候选池筛选数量，而不是只看到最终发布条数。

## 规则

- 时间窗口按北京时间自然日计算：发帖日当天、昨天、前天，默认由 `AI_DIGEST_MAX_AGE_DAYS=3` 控制。
- 生成上限和候选池分离：`AI_DIGEST_TARGET_ITEMS` 是发布上限，`AI_DIGEST_CANDIDATE_POOL_FACTOR=3` 控制先取约 `3x` 条候选再去重筛选。
- 去重包含 URL、标题和语义主题：
  - 同一模型、基准、产品、版本或开源项目只保留一条。
  - 被合并条目的 URL 会进入 `evidence_urls`。
- 类型优先级：
  - 优先：模型发布、版本升级、API/开发者工具、评测基准、开源项目、基础设施技术更新。
  - 补充：观点探讨、趋势评论、采用案例、行业观察。
- 排序顺序：
  - 北京时间日期优先，发帖日当天优先。
  - 同一天内先按类型优先级排序。
  - 同一类型层级内再按关注度、验证强度和来源多样性轮选。
- 正文会显示筛选数量，例如：
  - `候选池：抓取2098条，近3日10条，去重后9条，发布9条`

## 涉及实现

- `src/ai_digest/rank.py`
  - 新增 `ai_update_beijing_day_key()`，所有日期排序统一使用北京时间。
  - 新增 `ai_update_category()` 与类型优先级。
  - 新增语义主题 key，合并同一模型/基准/产品/版本的多链接条目。
  - 来源轮选只在同一天、同一类型层级内进行，避免观点类内容提前插到技术类前面。

- `src/ai_digest/collect.py`
  - metadata 增加 `fresh_count`、`deduped_count`、`duplicate_removed_count`。

- `src/workflow/create_post.py`
  - 新增候选池倍率 `AI_DIGEST_CANDIDATE_POOL_FACTOR`。
  - `source_meta` 记录 `candidate_pool_target`、`selection_pool_items`、`selected_before_body_fit`、`body_fit_dropped`。

- `src/ai_digest/generate.py`
  - LLM prompt 明确要求先去重、技术/模型类优先、探讨类补充。
  - 草稿正文写入候选池筛选数量。

- `src/ai_digest/render.py`
  - 封面 `今日重点` 使用北京时间日期和类型优先级选择。
